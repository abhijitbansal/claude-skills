# make-diagram stories Implementation Plan (master)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make-diagram pages that play named stories of beats (one hop along an edge, or a focus shot, each with a title and caption) behind a transport bar, let the reader explore nodes, edges and routes in a side panel, look like a dark glowing system map or archify's tinted cards, and go full screen — while the model still writes only `diagram.json`.

**Architecture:** Four phases on one branch. Phase 1 widens the spec (`stories`, `emoji`, `detail`, `autoplay`), resolves beats at build time into `viewerData.beats`/`chapters`, splits the 521-line `template/viewer.js` into runtime modules composed by `PADiagram.mount`, and ships the story player with its transport. Phase 2 adds Explore (panel, route, find) on the same data. Phase 3 is the look (theme tokens, kind colours, emoji tiles, lanes, pills, legend, glow and dot styling, default theme `blueprint`, goldens regenerated once). Phase 4 adds full screen with its fallback, mounts the full viewer in make-explainer's overlay, updates the docs, runs the eval, and rebuilds the gallery sample.

**Tech Stack:** Node ≥ 20 ESM, `node --test`, `ajv@8.20.0`, `elkjs@0.12.0`, Playwright 1.64 (dev; browser tests skip without a browser). Plain ES5-style browser scripts inlined into one HTML page under a strict CSP. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-14-make-diagram-stories-design.md` (approved 2026-10-14; do not change its decisions).

**Phase plans:** this file holds the file map, the cross-phase contracts and every phase's task list. Phase 1 is fully written in `2026-10-14-make-diagram-stories-phase1.md`. Phases 2–4 each get their own detailed plan file, written just before that phase runs against the code the earlier phases produced: `2026-10-14-make-diagram-stories-phase2.md`, `-phase3.md`, `-phase4.md`.

## Global Constraints

- Branch `feat/diagram-stories` (off `feat/visual-artifacts`, PR #38, not merged). One branch, one commit per phase or logical boundary. Implementers do **not** run `git commit` or `git push`; the orchestrator commits.
- Plain ESM Node (Node 20). No new npm dependencies anywhere. `shared/` stays zero-dependency.
- Output page CSP exactly: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:`. No inline event handlers, no `eval`/`new Function` in page code, no external requests at build or view time.
- Files under `template/` stay under 400 lines each; every other file under 800.
- The model writes only `diagram.json`; `validate.mjs` → `build.mjs` → `check.mjs` is unchanged as a workflow. Every new spec field is optional; existing specs build unchanged (their look changes in phase 3).
- `scripts/lib/api.mjs` keeps exactly the exports `buildDiagram`, `validateSpec`, `viewerRuntime` with their signatures (`test/api.test.mjs` pins the set). New helpers live in other modules.
- Existing `viewerData` keys (`type, title, stem, animate, width, height, steps, ids, adjacency, edges, parents, boxes, frames`) keep their shapes; new keys are additive.
- Limits (spec §1): `stories` ≤ 8, beats in all ≤ 60, story title ≤ 40 characters, beat title ≤ 48, caption ≤ 160, `detail` ≤ 400; `emoji` is exactly one emoji grapheme.
- Every validation error names the JSON path, the problem and the fix, with a did-you-mean where the value comes from a closed set.
- Every built example stays under the 400 KB page limit (`MAX_PAGE_BYTES`, `test/check.test.mjs`).
- Deterministic builds: same spec and versions give byte-identical HTML.
- Reduced motion: no travelling dot, the camera jumps, `autoplay` is ignored, manual stepping works.
- Every control has an accessible name; nodes are reachable with Tab; colour is never the only signal.
- `plugins/portable-artifacts/shared/` is the source; the skill copies under `skills/*/shared/` are generated by `node bin/sync-shared.mjs` and never edited by hand.
- Goldens (`test/golden/*`) are regenerated once, in phase 3's look commit, and that commit message says so. Never regenerated to hide an unrelated failure.
- Design skills for phase 3 implementers: `redesign-existing-projects` (static look) and `emil-design-eng` (dot and camera motion); never two design rulebooks loaded at once.

## Review Focus

Inputs the spec implies but no task's tests would otherwise exercise, most likely to bite first. Each line names the phase-1 task that pins it (phases 2–4 add their own in their plan files).

1. **A reply pair** (`a → b` and `b → a` both exist) named by `from`/`to`: the direction given must win, never an "ambiguous" error; only the *missing* direction plays in reverse. Pinned in phase 1 Task 2 (`resolveEnds`) and Task 3 (`beatsOf` on the story example, whose `orders ⇄ gateway` pair is such a case).
2. **A hop onto an edge that ends at a group** (architecture): the camera box must come from the group's box and the dot must still find the edge path. Pinned in phase 1 Task 3 (unit: `ids` holds the group id) and Task 5 (browser: the story example's focus beat lights a group; a hop to a group end has a finite camera).
3. **Ids named like `Object.prototype` members** (`constructor`) in stories, beats, `info` and `directed`. Pinned in phase 1 Task 3 (`test/ids.test.mjs` loops `info`/`directed`) and Task 5 (`PROTOTYPE_NAMED_SPECS` gains a story).
4. **A timeline of exactly one beat**: next/prev clamp, the scrubber has `max="0"`, play ends at once, loop replays. Pinned in phase 1 Task 6.
5. **Hostile text** (`<b>&"x"`) in story titles, beat titles and captions must reach chips and the caption line as text. Pinned in phase 1 Task 5.

## Cross-phase interface contracts

Exact names. Later phases consume these; phase 1 produces them.

### `scripts/lib/stories.mjs`

```js
/** [{ id, from, to, both }] for every graph edge (ids as the layout assigns them: authored, else `edge-<i>`) or message. */
export function linksOf(spec)
/** { link, reverse } or { error }: the direction given wins; else the one edge the other way plays in reverse. */
export function resolveEnds(from, to, links, what = 'edge')
/** Validation of `stories` (counts, lengths, story ids, every beat's target). ctx = { endpoints, known }. */
export function checkStories(errors, spec, ctx)
/** { beats, chapters }: from `stories`, else from `steps` (buildDiagram's, "Everything" included) as one chapter titled Walkthrough. */
export function beatsOf(spec, steps)
```

### `viewerData` new keys (`scripts/lib/data.mjs`)

```jsonc
{
  "autoplay": false,                       // spec.autoplay === true
  "beats": [                               // the timeline, in play order
    { "kind": "hop",   "chapter": 0, "title": "The app calls the API", "caption": "One POST.", "edge": "place", "reverse": false, "ids": ["app", "gateway"], "reveal": [], "highlight": [] },
    { "kind": "focus", "chapter": 1, "title": "The whole core", "edge": null, "reverse": false, "ids": ["core"], "reveal": [], "highlight": [] },
    { "kind": "step",  "chapter": 0, "title": "The API writes the order", "edge": null, "reverse": false, "ids": ["api", "db"], "reveal": ["db"], "highlight": ["db"] }
  ],
  "chapters": [ { "id": "placing", "title": "Place the order", "start": 0, "end": 6 } ],   // end exclusive; steps give [{ id: "walkthrough", title: "Walkthrough", start: 0, end: N }]
  "info": {                                 // per id: node/participant, or edge/message
    "orders": { "label": "Orders service", "kind": "service", "emoji": "📦", "note": "…", "detail": "…" },   // emoji/note/detail only when set
    "place":  { "label": "POST /orders", "style": "solid" }                                                   // label only when set; messages: style = message kind
  },
  "directed": { "app": ["place"], "orders": ["edge-3", "edge-4", "edge-6"] }   // id -> edge ids leaving it along the arrow; a `both` edge leaves both ends; the other end is edges[e]
}
```

`caption` is present only when the beat has one (a step beat's `note` becomes `caption`). One timeline is all `step` beats or none. `ids` is what the camera fits and the player lights (hop: the edge's ends, one id for a self edge; focus: the listed ids; step: the step's `focus`). `reveal` is the step's `show`.

### Template modules (`template/*.js`, each an IIFE registering on `window.PADiagram`)

PADiagram.camera(stage, svg, data, { onApply })          // -> { size, fitScale, fitCamera, apply, moveTo(target, { instant, ms }), cancelTween, fit, refit, zoomAt, zoomBy, panBy, boxOf, unionBox, cameraFor, ensureVisible, reduced, reduceQuery, zoom, isFitted, unfit, onResize }

## Decisions made where the spec is silent (defaults chosen; see each phase plan)

1. `from`/`to` when edges exist in both directions: the direction given wins (forward); only when no edge runs that way does the single reverse edge play backwards. A `both: true` edge follows the same rule.
2. Did-you-mean candidates for `edge` include the generated `edge-<i>` ids (an unnamed edge is addressable by that id, as `references/schema.md` already says).
3. `emoji` and `icon` both set: allowed; the emoji is drawn (phase 3) and the icon ignored.
4. A focus beat holds for the same time as a hop (2.5 s + 40 ms per caption character, capped at 6 s, divided by speed) after the 600 ms glide; it has no dot.
5. `F` stays fit until phase 4; phase 4 moves full screen onto `F` and fit onto `0`, the Fit button and double-click.
6. `P` while already in Play does nothing (Space is play/pause); Esc leaves Play when no panel or full screen is open (today's behaviour, kept).
7. The `#step-N` deep link keeps its name.
8. `data.steps` stays in the page data for every spec; `data.beats` is the timeline; `check.mjs` counts beats. `[data-pa-count]` keeps the `n / N` text and the page prefixes the word `Beat`, so make-explainer's current overlay needs no change in phase 1.
9. Story ids are their own id space (must match the id pattern and be unique among stories; they may equal a node id).
10. `stories: []` is an error (`at least one story is required — or remove stories`), like `nodes: []`.
11. The hover/focus/pin trace is inactive while in Play mode (its dimming would fight the beat's dimming); Explore mode keeps it.
12. The runtime has five modules in phase 1 (`transport.js` joins the four the spec names) so every template file stays under 400 lines.
13. A focus beat that names a group lights the group's members too; a hop lights only its own edge (not a second edge between the same ends). Everything else outside the beat dims (`pa-dim`).
14. Pausing hides the dot; resuming replays the current beat from its glide.
15. The Play story tab (and `P`) enters Play paused on beat 1; the transport's Play button (or Space, or `autoplay`) starts the timer.

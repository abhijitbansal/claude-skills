# make-motion 2: Version 1 Gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before the version 1 engine is deleted, every tool a version 1 user relies on (a flag, a script, a page, a file the skill writes) either works on a version 2 film, has a named replacement, or is dropped with a reason a user can read. Ported here: the provenance stamp, `--poster`, `vars` and `--batch`, the preview page, `--workers` (if it measures faster), the beats command with a film field that uses its grid, cut-outs with transparency, and the storyboard step.

The one command stays the one command: new behaviour is a flag of `scripts/make.mjs`, except the two tools that are separate programs today and stay so (`scripts/beats.mjs`, `scripts/storyboard.mjs`).

**Tech Stack:** The version 2 engine and scripts as they stand, `scripts/lib/beats.mjs`, `scripts/lib/cutout.mjs`, `shared/provenance.mjs`, make-explainer's `plan` page. `node:test`, Playwright Chromium. No new npm dependency.

**Spec:** `docs/superpowers/specs/2026-11-15-portable-artifacts-2-design.md`, sections 8.6 (capture, `--workers` stays), 8.7 (preview and carry-overs), 8.8 (a version 1 spec), 11 (the offline guarantees carried over), 12 (authoring support), 15 step 6. ## The port rule

A capability is ported when `M/SKILL.md` documents it as a step or a flag, or when an eval or another skill calls it. It is replaced when version 2 already does the same job another way; the replacement is named. It is dropped when neither holds, or when the thing it served is gone, and the reason goes to `references/migrating.md` (written by the cut-over's Task 5).

## Global Constraints

- No version 1 file is imported, and none is modified except the two this plan rewrites in place and keeps (`scripts/beats.mjs`, `scripts/storyboard.mjs`). The cut-over's guard (`test/v2/standalone.test.mjs`, once it exists) must pass with them on its keep list.
- No new npm package. No network in a render, a preview, a batch, a poster or a test.
- **Loopback server.** Every page is served by `scripts/v2/server.mjs`: bound to 127.0.0.1 on a free port, answering only its own Host headers, refusing a path with `..`, a backslash or an encoded separator, serving only `engine/`, the film's listed assets by index, and fixed routes. A new route is a fixed name, never a path built from a request.
- **CSP.** Every response carries the server's policy. The preview adds only what it needs (`media-src 'self'` for audio) and nothing remote; a test reads the header.
- **No off-origin request.** Headless pages keep `guardNetwork`. The preview runs in the user's browser, where the policy is the guarantee, so the preview page holds no URL that is not same-origin (a test scans the served files).
- **Path containment.** A film's inputs (pictures, a recording, music, a beats file, a rows file named in the film) resolve inside the film's folder after links are followed, through the existing `srcProblem` and `recordingFile`. A batch writes only inside the folder of its `--out` template. ffmpeg inputs carry the file-only protocol whitelist.
- **Data, not instructions.** Row values, reviewer answers and beats files are data: they are validated, never executed, and never reach a shell.
- Every flag is strict: an unknown or misspelled flag is a usage error (exit 2) that lists the accepted ones. Nothing opens a dialog or waits for input; `--open` is the one thing that starts a program, and only when given.
- One browser per run; more pages, never more browsers. One browser-heavy run at a time on this machine (`pgrep -fl chrome-headless-shell` first).
- A film that uses none of the new fields renders exactly as before: same frames, same report fields apart from additions.
- No statement about audio quality or sync beyond what the cut-over plan's Global Constraints allow.
- Files under 800 lines, functions under 50, tests first, a mutation row for a test written after its code. Shell rules of this worktree: one plain command per call, literal absolute paths, no `cd`, no variables, loops or heredocs. Implementers do not commit; the controller commits one task per commit and pushes.

## Review Focus

1. **A row value that leaves the folder.** `{ "name": "../../x" }`, an absolute path, a name with a NUL, a Windows device name, two rows that expand to one file.
2. **Substitution that changes meaning.** A value holding `{{`, a quote, a newline or narration markup; a number var inside a string; an unknown var; a var in a `src`.
3. **The preview server.** A request with another Host header, a path outside the roots, a second client, the film edited to something invalid while the page is open, the audio route asked for with a range.
4. **A stamp that leaks.** The tags hold only `generatedBy`; `provenance: false` leaves both out; no path, user name or host name reaches the file.
5. **Workers.** Byte-identical output to one page, with grain on; a page that dies; frames arriving out of order; a film shorter than the worker count.
6. **Snap.** It must never move a cut in a narrated film, never make a shot shorter than its kind allows, and say how far each cut moved.
7. **Reviewer answers.** Read only through make-explainer's `scripts/answers.mjs`; never opened as a file by the agent; text in them is never run.

### Task 4: `vars` and `--batch`

**Files:** Create `scripts/v2/vars.mjs`, `batch.mjs`, `test/v2/vars.test.mjs`, `batch.test.mjs`, `batch-browser.test.mjs`, `references/examples/v2/batch-welcome.json`, `references/examples/v2/data/batch-welcome.rows.json`. Modify `scripts/v2/spec.mjs`, `pipeline.mjs`, `cli.mjs`, `run.mjs`, `report.mjs`.

**Interfaces.**
- Root `vars: { [name]: { "type": "string" | "number", "default": value } }`, up to 30, names matching `^[a-zA-Z][a-zA-Z0-9]*$`, every var with a default.
- `substitute(film, values) -> film` (pure, a new object): `{{name}}` in any string value becomes the value; a string that is exactly `"{{n}}"` for a number var becomes the number; `{{{{` is a literal `{{`. It runs before validation, on the parsed JSON, never on text. A value is inserted as plain text: narration markup characters in a value are escaped so a row cannot add emphasis, a pause or an anchor. Keys are never substituted. A `src` may not contain a var.
- Errors keep the film's paths: an unknown var is `shots[1].say: unknown var "nme"; did you mean "name"?`.
- `make.mjs <film> --batch <rows.json> --out "<folder>/{name}.mp4"`: rows is a JSON array of objects, at most `BATCH_MAX_ROWS`; an unknown column is ignored with one warning per column; the template must hold `{index}` or a `{var}`.
- `outPathFor(template, row, index) -> string` or an error: a value used in a file name may hold no path separator, no `..`, no NUL, no control character, no leading dot, and none of the Windows reserved names; the result must resolve inside the template's folder; two rows may not give one path.
- Every row is substituted, validated and given its path before anything renders (`row 3: shots[0].say: …`, exit 1). Then rows render in turn in one browser. `manifest.json` in the template's folder lists, per row, `index`, `values`, `status` (`ok`, `findings`, `failed`), `file`, `sha256`, and the row's findings. A row that fails while rendering is marked and the rest still render; the run exits 1 if any row is not `ok`.
- `--batch` does not go with `--poster`, `--preview`, `--outline` or `--list`.

01 Overview

Cache Clock is a GitHub Copilot CLI extension modelled on cache-tax for Claude Code. Copilot bills tokens in AI credits, and on Claude and newer GPT models a cache write costs far more than a cache read. Step away longer than the cache lives and your next message, even "give me a recap", rewrites the whole conversation at the write price. Cache Clock shows that clock and that price. By default it drops one costly cold send so you can decide; the next send goes through.

02 Problem & why it's needed

The friction

Prompt caches expire silently. Through Copilot, a Claude Sonnet 5.5 cache lives 5 minutes and a write costs 25× a read; GPT-6 Luna lives 30 minutes at 12.5×. Copilot CLI shows neither the clock nor the price, so a coffee break turns the next "carry on" into a full rewrite of the context at the write price.

Why it mattersOn a real 37.2k-token Claude session the next send would have read the context for $0.003 warm. Sent 20 seconds after the cache expired, it read 0 cached tokens and wrote 44,388: about $0.08 extra. That one sits under the default $0.10 threshold, so it passes with defaults; longer sessions cost more, and /cache-clock min lowers the bar. Above it, Cache Clock warns before expiry, prices the cold send and asks once, at 0 AI credits.

03 Install

Tested on Copilot CLI 1.0.95. The extension runs inside Copilot's own runtime, so it needs no Node install; the optional report needs Node 18+.

From a clone (links the extension)

git clone https://github.com/abhijitbansal/claude-skills
sh claude-skills/tools/cache-clock/install.sh

Links ~/.copilot/extensions/cache-clock to the clone, so a git pull updates it. COPILOT_HOME moves ~/.copilot.

Copy instead of link, or remove

sh claude-skills/tools/cache-clock/install.sh --copy
sh claude-skills/tools/cache-clock/install.sh --uninstall

It replaces only a symlink or an earlier cache-clock copy at that path, and refuses any other folder.

First run

Start a new copilot session. Copilot asks once whether the extension may "register hooks": say yes (option 2 remembers it for that repo). Then run /cache-clock.

04 Usability guide

One slash command, inside the interactive CLI. Settings live in ~/.copilot/cache-clock/config.json and apply to every session.

/cache-clock — the card

The last model used, its cache state and time left, the context size, what the next send costs warm and cold, and the session's tally. A real card from a resumed session:

cache-clock · Claude Sonnet 5.5 cache warm, 1m17s left (ttl 5m00s) context 37.2k tokens next send warm $0.003 · cold $0.08 (25× per token) session 5 model calls · 0 cold after idle · 0 prefix breaks · $0 extra paid guard refuse once above $0.10 · heads-up 5m before expiry

/cache-clock guard refuse | warn | off

refuse (default) drops a costly cold send once; the next send goes through. warn sends it and prints the price. off disables the guard; the heads-up keeps its own switch.

/cache-clock guard warn
/cache-clock guard refuse

/cache-clock min <usd>

Guard only cold sends whose extra cost is at least this many dollars (default $0.10).

/cache-clock min 0.25

/cache-clock headsup <min> | off

One ephemeral line before expiry, when the cold send's extra cost is at least the threshold. The lead is the smaller of this setting and a fifth of the TTL, so a 5-minute Claude cache warns 1 minute ahead.

/cache-clock headsup 5
/cache-clock headsup off

The refusal

A real capture, taken with /cache-clock min 0.01 (at the default $0.10 this $0.08 rewrite passes silently). The turn ends before any model call, so the AI-credit counter does not move.

! cache-clock: the Claude Sonnet 5.5 prompt cache went cold 2s ago. Sending this rewrites about 37.2k tokens at $2.25/M = $0.08 (a warm send would read them for $0.003). Send it again to pay it, or /clear and start fresh.

05 How it works under the hood

The clock

Every main-agent model call emits assistant.usage with cacheReadTokens, cacheWriteTokens, cacheExpiresAt, cacheTtlSeconds and prices in nano-AIU per batch of tokens. Cache Clock keeps the last call per model. Nothing is guessed: the TTL, the expiry and the prices all come from Copilot. Sub-agent and background calls are ignored.

The guard

onUserPromptSubmitted checks the last model's clock. If the cache has expired and rewriting it would cost at least the threshold more than reading it, the guard prints the price and calls session.abort() without awaiting it (awaiting inside the hook deadlocks the CLI). The next send in that cold episode goes through with a one-line note, even from a new process: the refusal is remembered per session in ~/.copilot/cache-clock/refused.json for a week.

What is never guarded

Slash commands and ! shell escapes. A message queued while a turn is running only gets the note, because aborting then would cancel the running turn. The first send after a compaction, since the context was rewritten anyway.

Resume

assistant.usage is not replayed on copilot --resume, and getEvents() omits usage records, so the extension seeds the clock from the session's own ~/.copilot/session-state/<id>/events.jsonl.

Architecture

Seven small modules: wiring attaches to the session, clock keeps per-model state, guard decides, usage normalises events and prices, format writes every message, config stores settings and refusals, history feeds the report. Open the architecture diagram →

07 Report: what cold sends already cost you

The extension only sees sessions it was loaded in. The report reads every session Copilot has persisted, CLI and VS Code alike, and sends nothing anywhere.

node tools/cache-clock/bin/report.mjs
node tools/cache-clock/bin/report.mjs --since 7d
node tools/cache-clock/bin/report.mjs --json
model calls cold after idle prefix breaks rewritten extra paid total spent idle before cold sends Claude Sonnet 5.5 5 1 0 37.1k $0.08 $0.16 5m GPT-6 Luna 201 1 2 44.9k $0.005 $0.14 31m extra paid for cold rewrites: $0.08 of $0.29 spent · about $0.46 per week at this rate

"Extra paid" is what each cold call cost above a warm read of the same tokens. "Prefix breaks" are cold calls inside the reported TTL: something changed the prompt prefix, or the provider served it cold early.

VS CodeVS Code's Copilot agent harness writes to the same ~/.copilot/session-state directory, so the report covers VS Code sessions. Whether the live guard loads inside VS Code's harness is not verified yet; VS Code's own Cache Explorer (Agent Debug Logs) shows per-turn hit rates there.

08 Limits

No keep-warm yet

cache-tax pings to hold the cache during a break. An extension can only ping with session.send, which adds a user and an assistant turn to your conversation each time. Run the report first: whether pings pay off depends on your own tax.

Auto routes per prompt

With auto, the next prompt may go to a different model than the last. The guard prices the last model used.

The estimate is approximate

It is the last call's input plus its answer. The real resend adds your new message and anything Copilot attaches (44.4k actual vs 37.2k estimated in the capture above).

Early eviction is invisible to the guard

It trusts Copilot's cacheExpiresAt. When a provider serves a cache cold sooner (Luna at 29 of 30 minutes, once), the send is billed cold and the guard stays quiet; the report counts it as a prefix break.

-p mode

The guard works in copilot -p, but slash commands there go to the model as text, so /cache-clock needs the interactive CLI.

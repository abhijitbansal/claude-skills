How a request becomes a finished page

The portable-artifacts pipeline, from one request to one offline HTML page

Nodes

  • Person's request (user)
  • Claude Haiku agent (service): Writes JSON only
  • JSON spec file (other): diagram.json
  • Offline HTML page (client): No network requests
  • Group Build-time pieces
    • validate.mjs (service): Names the exact fix
    • build.mjs (service)
    • ELK layout engine (service): Runs locally, computes every position
    • make-dashboard renderer (service): Draws chart cards
    • make-motion renderer (service): Renders MP4 video
    • Shared themes (storage): dusk, press, poster and four more

Connections

  • Person's request → Claude Haiku agent: asks for a diagram
  • Claude Haiku agent → JSON spec file: writes one file
  • JSON spec file → validate.mjs: is checked
  • validate.mjs → Claude Haiku agent: returns the exact fix
  • validate.mjs → build.mjs: passes the spec on
  • build.mjs → ELK layout engine: asks for layout
  • build.mjs → make-dashboard renderer: renders chart cards
  • build.mjs → make-motion renderer: renders video scenes
  • Shared themes → build.mjs: supplies colours
  • build.mjs → Offline HTML page: writes one HTML file

At a glance

One JSON file becomes a page or video

This branch adds four agent skills that build offline dashboards, diagrams, explainer pages and short videos. The model writes only a small JSON file, and scripts validate, lay out and render it.

  • make-dashboard v2 builds live, offline dashboards from local data files.
  • make-diagram, make-explainer and make-motion add diagrams, pages and videos from JSON.
  • Every page makes no network requests and carries a strict Content Security Policy.

Four skills

Four skills share one JSON-to-page loop#

  • make-dashboard v2

    Builds one offline dashboard from CSV, Parquet, JSON, DuckDB or SQLite files. Its charts sort, compare and export, and the page reloads when the spec changes.

  • make-diagram

    Draws architecture, flow, sequence and state diagrams from a small JSON topology. Layout is computed at build time, so the model never writes coordinates.

  • make-explainer

    Builds one themed page or slide deck from typed sections. It can embed diagrams, charts and videos made by the other skills.

  • make-motion

    Renders a short MP4 video from a JSON list of scenes. Text, shapes, counters and transitions are all set in the file.

Getting started

Install once, then ask in plain words#

  1. Install the skills

    Run one of the install commands in the next section. The skills are added to your agent.

  2. Ask for a page

    Describe what to explain in plain words, or call the skill directly with a slash command.

  3. Validate the JSON

    The skill runs validate.mjs. Each problem prints a JSON path, the problem and the fix. The agent reruns it until the output says valid.

  4. Build the page

    The skill runs build.mjs, which writes one offline HTML page and prints its path. Open that file in any browser.

  5. Check the page (optional)

    Run check.mjs on the page. It looks for console errors and sideways scrolling at desktop and phone width.

Versus hand-written

Spec-driven pages cost less and stay consistent#

Hand-written AI pages

Caution
  • The model writes the HTML, CSS and script for every page, which costs more output.
  • Each run can produce a different look, and it often has the generic look of an AI page.
  • A small change can disturb the rest of the page.

Spec-driven pages

Good
  • The model writes only JSON, so the cheapest model passes the eval gates.
  • The same spec always gives the same page, and a change is one edited field.
  • Validation names the JSON path and the fix, so most errors are repaired in one or two runs.

Verdict. A spec keeps the cost low and the output the same from run to run.

Known limits

Five known limits each have a clear workaround#

SeverityRiskMitigation
Low An interactive chart needs a make-dashboard spec. Inline rows give a static chart only. Use a make-dashboard spec when the reader needs the interactive views.
Medium Explainer charts refuse Postgres and MySQL sources, so builds never reach the network. Export the data to CSV or Parquet first.
Low In a slide deck, browser find (Ctrl-F) searches only the current slide. Use page mode when the reader needs to search the whole text.
Low Each static chart ships four drawings, which adds weight to long pages. Keep long pages to a few charts.
Medium make-motion was not re-evaluated on this branch, so it is not pinned to a model. Check each video by hand before sharing it.

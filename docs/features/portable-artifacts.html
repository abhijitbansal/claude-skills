01 Overview

Two agent skills that do what hosted "artifact" features do, without a cloud, an account or a particular model. make-dashboard turns a prompt and a data file into one self-contained index.html of KPI tiles and Vega-Lite charts, where every chart expands to show its SQL, row count and refresh time. make-motion turns a prompt into a live preview with a scrubber and a deterministic 1080p MP4. They work with any agent that can read files and run shell commands, and an installer ports them to Codex, GitHub Copilot, Gemini CLI and Claude Code.

The design is spec-first: the model writes one small JSON spec, and deterministic Node scripts do everything else. Field-level errors from the validator drive the retry loop.

02 Problem & why it's needed

The friction

Hosted artifact features lock you to one vendor, need an account and the network, and regenerate whole pages of code for every small tweak — so "make the second scene slower" can change everything else too.

Why it mattersWriting JSON that matches a schema is a small job that weak and local models can do. A change is one field in the spec, never regenerated code, and the same spec always produces the same page or video. After a one-time install nothing touches the network except your own data sources.

03 Install

Claude Code — add the marketplace, then install portable-artifacts

/plugin marketplace add abhijitbansal/claude-skills
/plugin install portable-artifacts@claude-skills

Then ask for a dashboard or a video, or call a skill directly: /make-dashboard … or /make-motion …. On first use the agent runs the one-time npm ci inside the skill folder.

Codex, GitHub Copilot, Gemini CLI — or Claude Code without the marketplace

Each host reads skill folders from its own directory, and the skill itself is the slash command. The installer copies both skills to the right place and installs their dependencies.

git clone https://github.com/abhijitbansal/claude-skills
node claude-skills/plugins/portable-artifacts/bin/install.mjs codex # ~/.agents/skills
node claude-skills/plugins/portable-artifacts/bin/install.mjs copilot --project . # ./.github/skills
node claude-skills/plugins/portable-artifacts/bin/install.mjs gemini # ~/.gemini/skills + commands
node claude-skills/plugins/portable-artifacts/bin/install.mjs claude # ~/.claude/skills, no marketplace

If it can read files and run shell commands: copy a skill folder into your project, run npm ci inside it, and add one line to your AGENTS.md (or .github/copilot-instructions.md).

05 Usability guide

/make-dashboard — a dashboard from a data file

You say "Revenue by region and the monthly trend from data/sales.csv". The agent inspects the data, writes dashboard.json (sources, SQL queries, KPIs, Vega-Lite charts), validates it, and builds one offline index.html. Every chart expands to show its SQL, row count and refresh time. Rerun one command to refresh — no LLM involved. Sources: CSV, Parquet, JSON, DuckDB, SQLite, Postgres and MySQL.

/make-dashboard revenue by region and the monthly trend from data/sales.csv

/make-motion — an animated explainer

You say "8-second clip: Q3 revenue up 18%, then a bar chart of Q1–Q3". The agent writes motion.json, validates it, opens a live preview with a scrubber, and renders a deterministic 1080p MP4. "Slow scene 2" changes one field, not the whole video.

/make-motion 8-second clip: Q3 revenue up 18%, then a bar chart of Q1-Q3

Codex syntax

Codex invokes skills with $: $make-dashboard … or $make-motion … (or browse with /skills).

06 Security model

Dashboards run model-written SQL — read-only, boxed in

Each query must parse (DuckDB's own parser) as a single SELECT, and an allowlist over its syntax tree lets it read only the declared sources and its own CTEs: no query(), read_*, duckdb_*, system catalogs or sqlite_*/postgres_*/mysql_* bridges. It runs wrapped in a row limit and a timeout, against a DuckDB connection locked to the exact declared files (allowed_paths, external access off, configuration locked). Sources must live under the spec's folder unless you pass --allow-outside. For Postgres and MySQL, READ_ONLY only limits DuckDB: use a read-only database role. Credentials come only from environment variables and are scrubbed from errors and results as defence in depth; the SQL allowlist is the control.

Built pages embed the query results

Publishing index.html publishes the data.

No network from specs

Chart url/data/usermeta keys are rejected at any depth; motion colours can't be url(); pages run under a CSP without unsafe-eval; the renderer aborts any non-local request; local servers bind 127.0.0.1 and check the Host header.

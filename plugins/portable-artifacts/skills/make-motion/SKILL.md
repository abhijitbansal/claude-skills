# make-motion

You write one JSON file, `motion.json`. Scripts validate it, preview it in a browser and render it to MP4. You never write animation code, and you never edit generated output.

Run every command from the project folder (where `motion.json` lives), using the full path to the scripts. Image paths resolve relative to the spec file. If the request is empty, ask what the video should say, how long it should be, and the format (default 16:9, 30 fps). Before writing a spec, or handing the work to another agent, run the Intake (one round) section below, and put its answers in the hand-off brief.

**Audio is opt-in.** Add `audio` tracks only when the prompt asks for sound (music, soundtrack, voiceover, narration, "read it aloud", a sound effect, a click or a whoosh) or the user confirms when you ask. Never add audio to a prompt that does not mention it. A music or voice file the user names, in the prompt or in the intake round, counts as asking for that track. When the prompt is about sound but unclear (for example "make it feel polished" with an mp3 in the folder), put it in the intake round (see Intake (one round)) rather than asking separately. Music and sound effects are files the user supplies; a voiceover can be synthesised with `voice.mjs` (workflow step 2) when the prompt asks for narration without giving a file. Short UI-style sounds need no file: the root `cues` array (below) synthesises them locally.

## Intake (one round)

Before writing the spec, ask once. Send one message that lists every option below with its default, so the user can answer in one reply, or say "defaults". Ask before any hand-off to `artifact-builder` and put the answers in its brief. Leave out an option the prompt already settles ("a 9:16 clip", "with a voiceover") and say what you took from it. If the prompt already settles every option that matters, skip the round and build. Then build; do not ask again.

- **format**: `16:9` (default), `9:16` for Reels, TikTok and Shorts, `1:1` or `4:5`. Write the name you take as the spec's `format`; it sets the size.
- **platform**: none (default), or Reels, TikTok or Shorts. Picking one switches on viral mode (`"mode": "viral"`, see Viral mode): 9:16, the platform safe zone, captions and auto-placed cues.
- **length**: about 10 s (default); 8 to 30 s works well.
- **assets**: your own files in the project folder. Photos or a logo (PNG, JPG, SVG), clips (mp4, mov, webm, m4v), music and a voice file (mp3, wav, m4a, aac, ogg, flac). Default: none, so the video is built from text, shapes and charts. Naming a music or voice file here counts as asking for that track.
- **voiceover**: narration synthesised on this machine with Kokoro. Default: off. Saying yes means a one-time install of about 250 MB plus a 90 MB voice model (the doctor check in Before the first build asks again before it installs). A voice file in assets replaces it.
- **sound**: short synthesised cues (pop, click, whoosh, chime, impact, riser, swoosh, typing, drop, ding) or recorded ones (`kenney:` click, tick, switch, select, confirm, error, open, close, pluck, glass, thud, metal), or none. Default: none; the audio opt-in rule above stands.
- **theme**: `dusk`, `press` or `poster`, as in Choosing a theme. Default: the one that section picks for the prompt, `dusk` when unclear.
- **CTA**: a closing line and what to do (for example "Try it free at example.com"). Default: none.
- **captions**: on-screen words from an SRT, VTT or Whisper JSON file in the project folder, or from the voiceover's sentence timings, in one style: `plain`, `pill`, `karaoke` (the spoken word highlighted), `kinetic`, `boxed` or `typewriter`. Default: off; `plain` when on without a style.

If the prompt asks you to build and you cannot pause for an answer, skip the round and build with the defaults. That covers `claude -p`, `codex exec`, `copilot -p`, the eval, or any run that cannot pause for an answer. Do not ask a question in place of a spec. Your final report then carries one line with the value you actually used for each option, not the defaults when the prompt settled something else:

`intake: skipped (<reason>); values used: format <format>, length <seconds> s, assets <files or none>, voiceover <on or off>, sound <cues or none>, theme <name>, CTA <text or none>, captions <style or off>, platform <name or none>`

Fill `<reason>` with why you could not ask. With nothing settled by the prompt the line reads `format 16:9, length 10 s, assets none, voiceover off, sound none, theme <name>, CTA none, captions off, platform none`.

## Workflow

Run every step yourself, in this same turn, with your shell or file tools. Do not end your reply after showing or describing the JSON: keep going until validate prints `valid` and the output file exists.

1. Write `motion.json` in the project (shape below; full reference in `<skill-dir>/references/schema.md`; copy a file from `<skill-dir>/references/examples/` to start). Start from a block when one fits (see Blocks below): a title card, a lower third, a KPI number, steps, a quote, a checklist, a logo outro or a closing call to action is one `block` element with a few params, not a dozen elements.
   Actually create the file: describing it or announcing a patch is not enough. If your file tool fails, write it with a short `node -e` script that calls `fs.writeFileSync`, then confirm the file exists before validating.
2. Voiceover (only when asked, see above; run the doctor with `--for voiceover` first, and if the user declines the voice install, ask for a voice file instead): write the narration to `voice/<scene-id>.txt` (plain spoken text, no markdown), then `node <skill-dir>/scripts/voice.mjs --text-file voice/<scene-id>.txt --out voice/<scene-id>.wav [--voice af_heart] [--speed 1]` writes a 24 kHz wav and prints its length; it also writes `voice/<scene-id>.json` with sentence times (`{ sampleRate, voice, sentences: [{ text, start, end }] }`, seconds from the clip start), and prints that path on a third line; use it as a captions `src`. Use `--text-file`, not a quoted argument: the shell would expand `$4.2M` or backticks inside a double-quoted string and the clip would silently say something else. One clip per scene, scene-anchored in the spec (`"scene": "<id>", "at": 0.3`); keep each clip shorter than its scene (lengthen the scene if the printed duration does not fit). Voices: `af_heart` (default, warm US female), `af_bella`, `am_michael` (US male), `bf_emma` (UK female); `--list-voices` prints all. Write the narration text yourself from the prompt; keep it short and spoken, no markdown.
3. `node <skill-dir>/scripts/validate.mjs motion.json` — fix every line it prints (`<json.path>: <message>`, with did-you-mean) and re-run until it says `valid`. Exit 0 ok, 1 spec errors, 2 usage/IO error.
4. Self-check, look then check: `node <skill-dir>/scripts/render.mjs motion.json --contact-sheet` writes one tiled sheet per scene to `out/contact/<scene-id>.png` next to the spec. Each tile is the scene at one moment, stamped `<scene-id> · <seconds>s`: 0.1 s in, 0.1 s after each keyframe lands, 85% of the scene, and its last frame. A scene with more than 11 moments shows 11 of them (12 tiles in all) and says so on stderr (`<scene-id>: N moments, showing 11`). When the frame is wider than 360 px, the last tile repeats the last frame at 360 px wide, as a phone shows it. Open every PNG and look for clipped text, overlaps, invisible elements, wrong fonts, and text too small to read on the phone tile. Then run `node <skill-dir>/scripts/check.mjs motion.json [--theme <name>]` (run the doctor with `--for check` first; pass the same `--theme` you render with). It seeks the same kind of moments in the real page, all of them rather than only the 11 a sheet shows, and prints one line per problem (`scenes[i].elements[j]: <message>`, or `scenes[i]: …` for a whole scene): visible text or a counter outside the safe area (60 px at 1080 on the short side, on every side) while it is not moving; two visible texts or counters overlapping while neither is moving or fading (a cross-fade swap in one spot is fine); a scene that ends with nothing on screen; with `captions`, a text or counter held in the caption zone while a caption shows (`text "sub" sits in the caption zone (y >= 842) at 1.00s; move it above y 842 or end the captions before it`) and a captions layer outside the zone. An element that has left the frame entirely counts as gone, not clipped. Four audits follow. Contrast: a text's colour, at its alpha and opacity, must reach WCAG AA against the worst part of the pixels behind it (4.5:1, or 3:1 for large text), and the message names a passing theme token, or says to add a backing card or move the text when none passes over that background. Reading floor: a text must stay on screen 0.75 x (0.5 + 0.3 x words) seconds, give or take one 0.25 s step; a last line under 2 s that clears it is only an `info:` line on stderr. Dead stretch: nothing visible may stay unchanged for more than 3 s except in the final 3 s, so add motion, or set `"hold": true` on an element meant to sit still (on a group or a block it covers the children); the message names the elements to mark. Text floor: text drawn under 28 px at 1080 on the short side for 0.5 s or more is a problem, so raise its `fontSize`. A contrast or text-floor finding at a single moment is only a warning. Exit 0 ok, 1 problems, 2 usage error; without a browser it prints `check: skipped (no browser: …)` and exits 0, so rely on the sheets. Fix the spec and repeat both.
5. `node <skill-dir>/scripts/preview.mjs motion.json [--open]` prints a localhost URL with scrubber, play/pause, scene markers, Space and arrow keys. The page reloads when the file changes. It plays the audio tracks in sync (approximate; M mutes); the MP4 timing is exact.
6. Set `generatedBy` to the model you are running as, your effort level if you know it, and your host (for example Claude Code, Codex, Copilot CLI, Gemini CLI). Never guess; leave out any field you do not know. `--model`, `--effort` and `--agent` on render.mjs override it. `node <skill-dir>/scripts/render.mjs motion.json [--out out/video.mp4] [--fps 30] [--size 1920x1080] [--workers 4|auto] [--quality draft] [--loudness -14|off] [--true-peak -1] [--model <m>] [--effort <e>] [--agent <a>]` writes the MP4 (H.264, yuv420p; AAC audio when the spec has tracks). It prints the theme it drew (`theme: <name>`, first line), then the path and frame count. `--workers` (1-16 or `auto`) captures frames in parallel and gives the same MP4 as one worker; `--quality draft` renders half the size on each side with a faster encode for a quick look (neither flag goes with `--contact-sheet`); `workers: N` and `quality: draft (WxH)` are printed to stderr only. `--loudness <lufs>` (−30 to −5) normalises the mix to that integrated loudness with a two-pass `loudnorm` (`--true-peak <dbtp>`, −3 to 0, sets the ceiling, −1.5 by default); a spec's `loudness` field is the target without a flag, and `--loudness off` turns it off. The provenance goes into the MP4's `comment` and `artist` tags, and the preview page shows the same line in a footer.
7. Many versions of one video (one per name, city or customer): declare `vars` in the spec and write `{{name}}` where each value goes (see Spec shape), give every var a `default` so validate, preview and check work on the spec alone, put the values in a rows file (`[{ "name": "Grace" }, { "name": "Alan" }]`, a JSON array of objects whose keys are the var names; an extra column is ignored with a warning, `unknown column "cty" ignored; …`), and run `node <skill-dir>/scripts/render.mjs motion.json --batch rows.json --out "renders/{name}.mp4"` (the file name needs `{index}` or a `{var}`). Every row is checked before anything renders (`row 1: <json.path>: <message>`, exit 1); then each renders in turn, and `renders/manifest.json` lists each row's `status`, file and `sha256`. A row that fails while rendering is marked `failed` and the others still render (exit 1).
8. Cutting to music (only when the prompt names music to cut to; needs ffmpeg, doctor id `ffmpeg`): `node <skill-dir>/scripts/beats.mjs data/music.wav` finds the beat grid and writes `data/music.beats.json` beside it, printing the path and `120.17 BPM, 20 beats` (`--out file.json` names it; it never overwrites the audio, and replaces only an older beats file). The grid covers the sound, so `beat:0` is the first beat inside it. Exit 1 with `no steady beat found in music.wav (confidence 0.31; needs 0.5)` means the track has no steady beat: time the cuts by hand, or lower `--min-confidence` only if you can hear a beat. Check the `bpm` it prints against the track: it can be half, double or 2/3 of the tempo you hear. `--bpm 128` forces the grid at an exact tempo (the confidence is then how well that grid fits the onsets; 1 % off already fails with `the grid drifts … retry without --bpm, or with a tempo closer to the track's`); for a tempo you know only roughly, give `--min-bpm` and `--max-bpm` from about 0.8 to 1.25 times it (`--min-bpm 112 --max-bpm 175` for about 140). Known misreads, each fixed one of those two ways: a kick on 1 and 3 from about 115 BPM (half; rock at 150 reads 75), a slow groove with ghost notes below about 75 (double), bossa (half, 2/3 or double), polka (2/3), 6/8 (its eighth notes) and anything below 60 BPM (no beat). Three need care: a reggae one-drop reads at double, so keep that read and anchor on every other beat (`beat:0`, `beat:2`, …), because `--bpm` and the range put the grid half a beat late, on the off-beat chords; a half-time groove with 16th hats (trap) reads at half, so give `--bpm` only, never the range (it can lock on a confident wrong tempo), and at 144 give `--bpm 144 --min-confidence 0.4`; a swing of 70 ms or more reads at half on the straight hits, so keep that read (`--bpm` may put the grid on the late hits instead). Sparse clicks under heavy noise are refused: give `--bpm`. Narration can pass the gate: `--min-confidence 0.6` refuses it. With `--bpm` the gate measures how well that tempo fits the onsets, not whether there is a beat: forced on speech or a drone it can pass now and then, so force a tempo only on music. No flag fixes a song that changes tempo or a ritardando: the grid fits one part, so time those cuts by hand. `beat:0` is the first beat inside the sound: a pad or hum intro counts, a silent intro does not. Then write `"beats": "data/music.beats.json"` at the spec's root and `"beat:<n>"` (n from 0, the first beat) as a keyframe `t` (the beat's time inside its scene, so `"beat:12"` outside its scene is an error that names the scene's span) or as a cue, audio or captions `at` (video seconds, or scene seconds when it names a `scene`). An index past the end is `beat:40 does not exist; the file has 20 beats`; a `beat:` with no `beats` file is `"beat:3" needs a root "beats" file`. A beat that lands on a scene cut belongs to the next scene (it can fall a few milliseconds after the cut), so anchor a scene's last keyframe to the beat before it. Add the music itself as an `audio` track. A var can feed the index (`"beat:{{n}}"`; write the whole value as one string).

When asked for a change ("slow scene 2", "make the title blue"), edit only the fields the request names in `motion.json`, then validate again. Do not rewrite the spec from scratch.

When done, report the spec path, the MP4 path with its duration and size, and one line per scene.

## Spec shape

```json
{
  "size": [1920, 1080], "fps": 30, "background": "#0b0d12",
  "scenes": [
    { "id": "intro", "duration": 3, "transition": "fade",
      "elements": [
        { "id": "title", "type": "text", "text": "Q3 revenue up 18%", "x": 960, "y": 480,
          "fontSize": 96, "fontWeight": 700, "color": "#ffffff",
          "keyframes": [ { "t": 0, "opacity": 0, "y": 520 },
                         { "t": 0.6, "opacity": 1, "y": 480, "ease": "outCubic" } ] } ] } ],
  "audio": [
    { "src": "music.mp3", "volume": 0.4, "fadeOut": 2 },
    { "src": "voice.wav", "scene": "intro", "at": 0.5 } ]
}
```

- Root: `format` (`16:9`, `9:16`, `1:1` or `4:5`; a preset that sets the size, the safe area and the caption zone), `size` (default 1920x1080; leave it out when you set `format`, a `size` that disagrees with it is an error), `fps` (24, 25, 30, 60), `background`, optional `generatedBy` (`{ model?, effort?, agent? }`), optional `theme` (a shared theme name: `dusk`, `press`, `poster`, `paper`, `ink`, `blueprint`, `editorial`, `mono`, `brief` — its dark colours and fonts become the defaults; omit it for `dusk`), `scenes` (1–50, total ≤ 120 s), optional `mode` (`viral`, see Viral mode) with `viral` (`{ safeZone?, loop? }`), optional `loudness` (`{ integrated, truePeak }`, LUFS −30 to −5 and dBTP −3 to 0: the target `render.mjs` normalises the mix to, and reports it against), optional `vars` (`{ "name": { "type": "string" | "number", "default": "Ada" } }`, names like `city` or `firstName`, up to 30: `{{name}}` in any string value becomes the value, a number as its plain text, or the number itself when the whole value is `"{{n}}"` (so `"to": "{{count}}"` works, and a text needs words around a number var); in a spec with `vars`, write `{{{{` for a literal `{{`; for one video per row, see Workflow step 7), optional `beats` (the path of a beats file in the spec folder, written by `beats.mjs`; it lets a keyframe `t` and a cue, audio or captions `at` be `"beat:<n>"`, see Workflow step 8). Only `scenes` is required. For a vertical or square clip set `format` (`16:9`, `9:16`, `1:1`, `4:5`) instead of `size`; keep captions in the caption zone the format defines (the lower part of the safe area: from 78 % of the height down, 72 % for `9:16` and `4:5`), so keep other text above it.
- Audio track (optional root `audio` array, up to 20): `src` (relative to the spec, inside the spec folder; mp3, wav, m4a, aac, ogg or flac), `at` (seconds from the video start, default 0), `scene` (a scene `id`; `at` is then relative to that scene's start, so lengthening an earlier scene keeps a voiceover aligned), `duration` (trim, seconds), `volume` (0–1, default 1), `fadeIn` / `fadeOut` (seconds). `fadeOut` anchors to the `duration` trim or the video end; a clip that ends earlier gets no fade. No `loop`: a short music file just stops.
- Sound cue (optional root `cues` array, up to 30; opt-in like `audio`, a spec without it has no cue and no audio change, except in viral mode, which places cues unless you write `cues`): `cue` (`pop`, `click`, `whoosh`, `chime`, `impact`, `riser`, `swoosh`, `typing`, `drop` or `ding`, or a recorded click or hit as `"cue": "kenney:<name>"`, names: click, tick, switch, select, confirm, error, open, close, pluck, glass, thud, metal; synthesised cues for whooshes and risers), `at` (seconds, required except with `follow`), `scene` (a scene `id`; `at` is then relative to it, so retiming keeps the cue on its beat), `volume` (0–1, default 1, literal), `pan` (-1 left to 1 right), `note` (a pitch such as `A4` or `C#5`, for `pop`, `chime`, `impact`, `drop` and `ding` only). A `typing` cue with `follow: "<text id>"` clicks along with that text's typing (no `at` or `scene` then). A `whoosh` is loudest 0.4 s in and a `riser` builds for 1.6 s, so start them that much before the moment they mark. The sounds are generated deterministically at render time (the same spec gives the same audio), mixed with any `audio` tracks, and skipped by the preview. Use few: at most one `impact` and one `whoosh` or `riser` per clip, and nothing under continuous motion (see `references/motion-design.md`). After a render with audio, `render.mjs` prints `audio: <n> LUFS integrated, true peak <n> dBTP`; it is information, not a gate.
- Captions (optional root `captions` array, up to 20; off unless the prompt or the intake asks for them): `src` (relative to the spec, inside the spec folder: an `srt`, `vtt` or Whisper `json` file the user gives, or the voice sidecar `voice/<scene-id>.json`), `style` (`plain` (default), `pill`, `karaoke`, `kinetic`, `boxed` or `typewriter`), `at` and `scene` (timed like an audio track: give a voiceover's captions the same `scene` and `at` as its audio track; only one track may show at a time, so give a second track a later `at` or `scene`). Captions sit in the caption zone, 2 to 6 words at a time, over every scene; keep every other text box above the zone (its bottom edge above y 842 at 1920x1080, 1382 at 9:16). The 1382 holds only at `format: "9:16"` (at `format: "4:5"` the zone starts at y 972): a raw `"size": [1080, 1920]` with no `format` uses the 16:9 ratio (zone from y 1498), so for a vertical clip set `format`, not `size`. Never invent caption text in a file of your own unless the prompt gives the words; from the voice sidecar the word timing inside a sentence is estimated, so `karaoke` and `kinetic` follow the voice only roughly.
- Texture (optional root `texture`, off by default): `vignette` (true darkens the corners) and `grain` (0–0.15, static film grain per scene, seeded from the scene `id`, so renders stay identical). Both slow the render a lot (measured at 1080p: about 42 ms per frame for the vignette, 100 ms for grain, 187 ms for both, against 17–33 ms for none); add them only when the prompt asks for a filmic, grainy or vintage look.
- Scene: `id`, `duration` (0.2–60 s), `elements`, optional `background` (a colour, or `"art"` for the theme's seeded art full-bleed behind the elements), `transition` (`none`, `fade` (a fade-in from the background, 0.4 s unless `duration` is set), `crossfade` (the new scene fades in over the previous one, which stays fully visible beneath, over 0.4 s unless `duration` is set), `push`, `slide`, `wipe`, `zoom`, `blur` or `iris` (the new scene comes in over the previous one; every name but `none` and `fade` is an error on the first scene); write `{ "type": "push", "direction": "up", "duration": 0.6 }` to pick the edge (`left` default, `right`, `up`, `down` for push, slide and wipe, the edge the new scene comes from; `in` default or `out` for zoom and iris) and a 0.1–2 s `duration` (0.4 default); a root `transition` sets the default). Only one scene is visible at a time, except during a transition window; scenes play back to back. Example: `references/examples/transitions.json`. Do not put `fade` on scene 1: frame 0 is the video's thumbnail and `check.mjs` warns when it is blank.
- Camera (optional scene `camera`, off by default; for a push-in, a pan across a row of cards, a roll or a hit): `keyframes` (`t` as for an element's, each with any of `zoom` 0.5–3 (1 = none), `x` and `y` pan in canvas pixels (the camera looks at that point, so the picture moves the other way), `rotate` degrees, `ease`) and `shake` (`amount` 0–100 px, `hz` default 8, `seed` an integer 0–7918, default 1; the same seed always shakes the same way; it runs for the whole scene, so put it on a short scene of its own). It moves every element of the scene about the canvas centre, so keep text well inside the safe area where the camera settles: `check.mjs` judges every hold and the last frame, and does not judge a move while it runs, as for an element's own move (two equal keyframes are a hold, and a shake alone does not count as moving). A camera move or a shake counts as change for the dead-stretch audit (a tween between equal keyframes does not). The background (colour or `"art"`), captions, grain and the vignette do not move. Example: `references/examples/camera-push-in.json`.
- Every element: `id` (unique in the whole spec), `type`, `x`, `y` (canvas pixels; the anchor is the element centre; a group's children measure them from the group's centre instead), optional `opacity`, `scale`, `rotate` (degrees), `keyframes`, `hold` (`true` when the element is meant to sit still for more than 3 s; `check.mjs` then skips it in the dead-stretch audit).
- Types: `text` (optional `"role": "title"`: the theme's display font and, without `keyframes`, its kinetic entrance; `"typing": true` types it out from the scene start at 0.035 s per character with a caret, its box always the full text), `counter` (`from`, `to`, `decimals`, `prefix`, `suffix`; animate `value`), `shape` (`rect`, `ellipse`, `line`; a line is horizontal of length `width`, use `rotate` to angle it; animate `draw` 0–1; `"elevated": true` makes a rect a card, `"cap": "round"` and `"arrow": "end"` shape a line), `image` (`src` relative to the spec), `video` (`src` an mp4, mov, webm or m4v relative to the spec, `width`, `height`, `fit`; optional `trimStart` and `trimEnd` (seconds into the clip), `offset` (scene seconds before it plays; it holds its first frame before and its last frame after), `mute`, `volume` 0–1; its sound joins the mix unless muted and stops when its scene ends; needs ffmpeg and ffprobe), `chart` (`vegaLite` with inline `data.values`, `width`, `height`; animate `reveal` 0–1 for a left-to-right wipe), `group` (`children`: 1–40 elements, up to 3 groups deep, each positioned relative to the group's centre; the group's own `x`, `y`, `opacity`, `scale`, `rotate` and `keyframes` move them as one, so build a card or a lower-third once and animate it as a unit; child `id`s are unique across the whole spec), `code` (`code` with `\n` between lines, `lang` one of `text`, `javascript`, `typescript`, `json`, `bash`, `python`, `diff`, `go`, `rust`, `swift`, `yaml`, `html`, `css`, `markdown`, `width`; optional `fontSize` (28, the smallest that passes `check.mjs`), `height`, `highlight` (line numbers from 1, drawn on a `surface` row), `"diff": true` (lines starting `+` tinted good, `-` tinted bad) and `"typing": true` (types like a text); highlighted offline in theme colours: keywords accent, strings good, comments text3, numbers warn).
- `block` (see Blocks below): `block` (a block name) and `params` (its fields); it expands into a group of plain elements, so give its `x`, `y` and, if you like, `opacity`, `scale`, `rotate` and `keyframes`, but never its parts' styling.
- Keyframe: `t` (seconds inside the scene, sorted, ≤ scene duration; or `"beat:<n>"` with a root `beats` file, the time of beat n inside the scene), optional `ease`, plus any animatable props for that type. Per property: it holds the first keyframe's value before it, interpolates to each later keyframe using that keyframe's `ease`, and holds the last value after. A property missing from a keyframe is interpolated across it. Frame *i* samples t = i/fps, so put the final keyframe at least one frame (1/fps s) before the scene end. A counter with no `value` keyframes counts from→to over min(2 s, 80% of the scene) with outCubic.
- Eases: `linear`, or `in|out|inOut` + `Quad|Cubic|Quart|Back|Elastic|Bounce|Sine|Expo|Circ`, or the named `enter` (entrances), `exit` (exits), `move` (from one place to another) and `land` (a small overshoot; once per clip). Prefer `enter` (or `outCubic`) for entrances.

## Blocks

A block is a ready-made piece of a scene. Write one `block` element and its `params`; it lays itself out for the canvas (16:9 or 9:16 alike), takes its colours from the theme and enters with a short stagger. Run `node <skill-dir>/scripts/blocks.mjs show <name>` for a block's params, defaults, where it goes on each format and a ready element to paste; `node <skill-dir>/scripts/blocks.mjs list` lists them all.

| block | use it for | params (`?` optional) |
|---|---|---|
| `title-card` | an opening or section title | `title`, `subtitle?`, `kicker?` |
| `lower-third` | naming a speaker or a product on screen | `name`, `role?`, `side?` (`left` or `right`) |
| `kpi-counter` | one headline number that counts up | `label`, `to`, `from?`, `prefix?`, `suffix?`, `decimals?`, `delta?` |
| `step-flow` | a process of 2 to 6 steps | `steps` (each up to 24 characters), `direction?` (`row` or `column`) |
| `quote-card` | a customer or press quote | `quote` (up to 200 characters), `attribution?` |
| `checklist` | 2 to 8 items ticked off one by one | `items` (each up to 40 characters), `tickAfter?` (seconds) |
| `logo-outro` | the closing logo and tagline | `src` (a logo file next to the spec), `tagline?`, `width?` |
| `cta-close` | the closing ask | `headline`, `action` (up to 24 characters), `url?` |
| `cta-soft` | a soft closing ask for short-form video: save, send, follow, comment, part 2 | `line` (up to 40 characters), `actions` (1 to 3 of `save`, `send`, `follow`, `comment`, `part-2`) |
| `story-beats` | a five-beat story told one beat at a time: hook, problem, reveal, proof, call to action | `hook` (up to 48), `problem`, `reveal`, `proof` (each up to 80), `proofNumber?` (`{ to, prefix?, suffix?, decimals? }`), `cta` (up to 40), `beatSeconds?` (1.5 to 4) |
| `listicle` | a title and 2 to 5 numbered rows that arrive one at a time | `title` (up to 40), `items` (each up to 40), `numbered?`, `itemSeconds?` (1 to 4) |
| `before-after-swipe` | two pictures or clips, the after one swiping in over the before | `before`, `after` (each `{ src, label }`, label up to 16), `headline?`, `swipeAt?` |
| `code-typing` | code typed into an editor panel, highlighted | `code` (up to 1700 characters), `lang`, `title?` (up to 60) |
| `code-diff` | a code change: removed lines red, added lines green | `before`, `after` (each up to 2000 characters), `lang`, `title?` (up to 60) |
| `terminal-run` | a command typed into a terminal, then its output line by line | `command` (up to 120), `output` (1 to 12 lines, each up to 80), `prompt?` (default `$`) |

```json
{ "id": "kpi", "type": "block", "x": 960, "y": 540, "block": "kpi-counter",
  "params": { "label": "Monthly active users", "to": 48200, "delta": "+12% on last month" } }
```

- `x`, `y` is the block's centre: the canvas centre (`960, 540` at 16:9, `540, 960` at 9:16) for `title-card`, `kpi-counter`, `logo-outro`, `cta-close`, `cta-soft` and `story-beats`. `checklist`, `step-flow`, `quote-card`, `listicle`, `before-after-swipe`, `code-typing`, `code-diff` and `terminal-run` go higher, centred above the caption zone: `960, 451` at 16:9, `540, 721` at 9:16; there they shrink their spacing and text (never below 40 px at 1080) to stay above the zone when the spec has captions. The code blocks are the exception: their titles keep the 40 px floor, but the code itself is 32 px, then 28 px (the text floor), then smaller when it still does not fit, which `check.mjs` reports so you shorten the code. `lower-third` is different: its `x`, `y` is the **bottom corner of the card's outer edge**, and the card grows up and inward from there, so its bottom stays at `y` however long the name. Left side: `x 100, y 818` at 16:9, `x 100, y 1358` at 9:16. Right side (`"side": "right"`, `x` is then the right edge): `x 1820, y 818` at 16:9, `x 980, y 1358` at 9:16. At those places the card is always above the caption zone. `blocks.mjs show <name>` prints these for every format.
- Block text is never smaller than 40 px at 1080 **on the short side**, so it scales with the canvas: on a 16:9 video watched on a phone it is small (a 1920-wide frame shrunk to a phone's width). For phone-first video (Reels, TikTok, Shorts) use `format: "9:16"`, where the same blocks fill the screen.
- Strings are short (80 characters unless the table says less) and lists are capped; the validator names the param (`scenes[0].elements[1].params.title: must NOT have more than 80 characters`). Shorten the text rather than splitting the block.
- Give a block's scene at least 3 to 4 s (a `checklist` of 8 items about 5 s); in a shorter scene its entrances are squeezed so nothing moves after 85 % of the scene. `story-beats` and `listicle` run on a schedule and the validator refuses a scene shorter than it (`params.beatSeconds: 5 beats × 2.4s need a scene of at least 12s`, `params.itemSeconds: 3 items × 2s need a scene of at least 6.8s`): lengthen the scene or shorten `beatSeconds` or `itemSeconds`. `code-typing` and `terminal-run` type at 0.035 s a character and say the same at `params.code` or `params.command` (100 characters of code need 3.54 s; a command, 0.8 s to come in, then 0.15 s per output line). A `before-after-swipe` needs a scene that holds its swipe (`swipeAt` + 1 s; the default `swipeAt` is 0.4 of the scene, so at least 1 s), and a `src` may be a video (`mp4`, `mov`, `webm`, `m4v`; it needs ffprobe to validate and is muted); a picture is simpler.
- Blocks add no sound; add `cues` yourself if the prompt asks for sound (viral mode places cues unless you write `cues`).
- A block in the first scene starts invisible (but for a `listicle` title and a `story-beats` hook, which are on from frame 0), so frame 0 (the thumbnail) is blank and `check.mjs` warns; put a plain text beside it or use `"background": "art"` when the thumbnail matters. In viral mode a `title-card` title, a `cta-close` headline, a `quote-card` quote on its card or a `listicle` title is on screen from frame 0 instead, and a `story-beats` hook always is. `cta-soft` and `before-after-swipe` have no hook of their own: when one opens the video, put a 3 to 7 word `"role": "title"` text beside it.
- In viral mode blocks lay out inside the platform safe zone and above the lifted caption zone: `blocks.mjs show <name>` prints the place as `viral 9:16 x … y …` (`503, 644` for the centred blocks; a left `lower-third` at `160, 974`).

## Viral mode

For Reels, TikTok and Shorts. Switch it on with `"mode": "viral"` when the prompt says Reels, TikTok, Shorts or viral, or the intake picks a platform. It sets defaults and adds `check.mjs` warnings; nothing in it ever fails a check.

- Defaults: `format` `9:16` (1080x1920) unless you write `size` or `format`; a platform safe zone of top 290, bottom 675, left 120 and right 195 px at 1080x1920 (the platforms' UI bands); captions in a zone lifted above the bottom band (y 998 to 1245, x 120 to 885); `loudness` −14 LUFS integrated, −1 dBTP true peak (`render.mjs` normalises the mix to it with no flag, and prints the measured level against it as `on target` or `off target`; a mix of cues alone needs a limiter stage for that, which needs ffmpeg 5.1 or later (an older ffmpeg gives a plain gain, a stderr note and `off target`); `render.mjs <spec> --loudness off` skips the normalising, and `--loudness -16` or `--true-peak -2` change it for one render); and, with no `cues` key, cues placed for you: a `swoosh` on each cut, a `pop` on each entrance, a `ding` when a counter lands, at least 0.4 s apart. Write `"cues": []` for none (do so when the prompt asks for a silent clip), or your own list to replace them.
- The first scene's title is the hook: 3–7 words, on from frame 0. A `"role": "title"` text without keyframes in the first scene does this by itself (it starts visible and settles from a slight scale; `"exit": true` still works). Not inside a group that fades in: frame 0 could not show it, so it keeps the theme entrance.
- Keep every other text inside x 120 to 885 and y 290 to 998 (centre x 502): text under a band is hidden by the app's buttons and caption.
- Cut, reveal or move something at least every 3 s.
- Captions on whenever there is speech (the voice sidecar or an SRT): Reels, TikTok and Shorts are mostly watched muted.
- End with a soft call to action (save, send, follow for part 2), such as a `cta-soft` block (a line and pills such as "Save for later" and "Follow for more") or a plain closing text held at least 2 s, and, for a loop, repeat the hook in the last 0.6 s and set `"viral": { "loop": true }` so `check.mjs` compares the last frame with the first.
- The safe-zone numbers are tunable defaults from the platforms' ad specs, not rules, and −14 LUFS is a common default that no platform publishes; `"viral": { "safeZone": { "top", "bottom", "left", "right" } }` overrides the zone (px at 1080x1920; left + right at most 720, top at most 758, bottom at most 762, so the content and two caption lines keep room).
- `check.mjs` warns (`warning: viral: …`, or `warning: <element path>: viral: …`): a format other than 9:16, `audio` without `captions`, no text at frame 0 or a hook outside 3–7 words, a held text under a band, more than 3 s with no change in the final seconds or among `hold` elements (without a browser, read from the keyframes and captions), and with `loop` a last frame that does not match the first. Start from `<skill-dir>/references/examples/viral-hook.json`.

## Choosing a theme

Nine themes exist; `dusk` is the default. Pick one (the spec's theme field, or `--theme <name>` on the render) in this order:

1. A theme the user names ("use poster") wins. Use it as given: write it as the spec's theme field. On the render, `--theme <name>` only fills in for a spec that names none, so a theme already in the spec wins over the flag.
2. Otherwise infer it from the prompt and say which theme and why in one line. Dense docs, long reads, changelogs and branch recaps: `press`. Launch decks, pitches, demos and energetic clips: `poster`. Everything else, or unclear: `dusk`.
3. If the prompt is genuinely split between two themes, ask the user in the intake round (`## Intake (one round)`), not separately, and list all three with a one-line feel each: `dusk` is soft, warm and playful; `press` is print editorial, calm and long-form; `poster` is loud, condensed and high-energy.
4. If you cannot ask, use `dusk`.

The older themes `paper`, `blueprint`, `ink` and `editorial` stay available by name; use one only when the user names it. Two more are available by name only: `mono` (terminal and engineering console, dark mode near-black with a cyan accent) and `brief` (executive, warm white with a burgundy accent); `mono` and `brief` are the plan-page themes of make-explainer (see its Plan mode).

## Style defaults

The `dusk` theme when the spec names none: its dark page colour, Host Grotesk for text, Commit Mono for `"font": "mono"`, Funnel Display for `role: "title"`; 1920x1080 sizes (titles 72–120 px, body 40–48 px, captions ≥ 28 px). Charts get a dark theme automatically; put a Vega-Lite `config` in the chart to override it. Keep entrances 0.6–0.9 s, stagger 0.09 s per word or 0.2–0.25 s per list item, and stay under 15 s unless asked. For timing, holds, the named eases and `"exit": true` (a titled text's opt-in exit before a scene cut), read `<skill-dir>/references/motion-design.md`. Fonts are bundled; never use CDN URLs. Charts must carry inline data (`data.values`, or `datasets` + `data.name`); any `url` in a chart spec is rejected. Colours must be hex, rgb()/hsl() or named; a shape `fill`/`stroke` or text `color` may instead name a theme token (`surface`, `line`, `accent`, `accentSoft`, `good`, `bad`, `warn`, `text`, `text2`, `text3`, `cat1`..`cat6`), which follows the theme. For cards use `"fill": "surface"` with `"stroke": "line"` and `"elevated": true`, not hand-picked hex.

## Degraded mode

If Node, Chromium or ffmpeg cannot be installed here, still write and validate `motion.json` (validation needs only the skill's `node_modules`: run the doctor), then give the user the exact preview and render commands above to run themselves.

## Voiceover and audio notes

What the scripts do, and why:

- `voice.mjs` disposes the ORT session (`tts.model.dispose()`) in a `finally`; on failure it sets `process.exitCode` (never `process.exit()`) and lets the event loop drain. Exiting with a live session, or calling `process.exit()`, aborts with exit 134 / `mutex lock failed`. Keep it that way if you edit or wrap the script.
- Long narration is synthesised sentence by sentence: the text is split into sentences capped at 300 characters, each goes through its own `tts.generate()` call and the clips are joined, because Kokoro truncates one call at about 27 s. Pass the text with `--text-file`, never as a quoted argument.
- `amix` takes the first input's sample rate and channel layout, so every track is normalised with `aformat=sample_rates=48000:channel_layouts=stereo` before mixing and the encode pins `-ac 2`. Without it a mono 24 kHz voice listed first collapses stereo music.

## Security

The preview server binds 127.0.0.1 only and accepts only local Host headers, and serves only this skill's own folders plus the image, video and audio files the spec names (and, for render and check, the frames decoded from those videos). The renderer aborts every non-local request and sends a strict CSP. The validator is not the offline guarantee; the CSP and the renderer's request abort (`guardNetwork()`) are. No network access at validate, preview or render time. The one exception is `voice.mjs`: its first run downloads the Kokoro voice model (about 90 MB) from huggingface.co into `<skill-dir>/.cache/models`, after which it is offline too.

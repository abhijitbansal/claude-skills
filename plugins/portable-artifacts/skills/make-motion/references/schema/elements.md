# motion.json reference: elements: text, counter, shape, image, chart, video, lottie, group, code and their notes

Part of the reference indexed in ../schema.md.

## Elements
Common: `id` (unique across scenes and elements), `type`, `x`, `y` (required; canvas pixels, except a group's children, whose `x`, `y` are relative to the group's centre), `opacity` (0–1, default 1), `scale` (1), `rotate` (deg, 0), `keyframes`, `hold` (boolean, false: this element may sit still for more than 3 s; on a group or a block it covers every child; see `check.mjs` below).

| type | extra fields | animatable props |
|---|---|---|
| `text` | `text` (req), `role` (`title` only; see below), `exit` (boolean, false; see below), `typing` (boolean, false; see below), `fontSize` (48), `fontWeight` 400\|500\|600\|700\|800 (600), `color` (the theme's text colour), `align` left\|center\|right (center), `anchor` left\|center\|right (center; see below), `maxWidth`, `font` sans\|mono | opacity x y scale rotate (+ `value` when `typing`) |
| `counter` | `to` (req), `from` (0), `decimals` (0), `prefix`, `suffix`, `group` (false; `true` prints 48,200, not 48200), + text styling | + `value` (starts at `from`) |
| `shape` | `shape` rect\|ellipse\|line (req), `width`, `height`, `radius`, `fill`, `stroke`, `strokeWidth`, `elevated` (rect only), `cap` and `arrow` (line only) | + `draw` 0–1 (stroke reveal; default 1) |
| `image` | `src` (req, relative to the spec file; must stay inside the spec folder, be a regular file, no symlinks out, no dotfiles), `width`, `height` (req), `fit` contain\|cover\|fill, `grade` (a colour grade; see Grade below) | opacity x y scale rotate |
| `video` | `src` (req; same path rules as image; `mp4` \| `mov` \| `webm` \| `m4v`), `width`, `height` (req), `fit` contain\|cover\|fill (contain), `trimStart` (s into the clip, 0), `trimEnd` (s into the clip, the clip length), `offset` (scene s before it plays, 0), `mute` (false), `volume` 0–1 (1), `grade` (see Grade below); see below | opacity x y scale rotate |
| `chart` | `vegaLite` (req, with inline `data.values`, or a bundled map as `data: { "name": "world-110m" }`; see Maps below), `width`, `height` (req) | + `reveal` 0–1 (left-to-right wipe; default 1) |
| `group` | `children` (req, 1–40 elements; see below) | opacity x y scale rotate |
| `block` | `block` (req, a block name), `params` (req, that block's fields); see Blocks below | opacity x y scale rotate (the whole block) |
| `code` | `code` (req, up to 10,000 characters; `\n` starts a line), `lang` (req: `text`, `javascript`, `typescript`, `json`, `bash`, `python`, `diff`, `go`, `rust`, `swift`, `yaml`, `html`, `css`, `markdown`), `width` (req), `height` (a minimum; longer code makes the box taller), `fontSize` (28), `highlight` (1-based line numbers), `diff` (boolean, false), `typing` (boolean, false; as on a text); see below | opacity x y scale rotate (+ `value` when `typing`) |
| `lottie` | `src` (req; a Lottie JSON file, same path rules as image; at most 4 MiB), `width`, `height` (req; the animation is fitted inside, centred), `offset` (scene s before it plays, 0), `speed` 0.25–4 (1); see Lottie below | opacity x y scale rotate |
| `icon` | `name` (req, a Lucide icon name; `node scripts/sketch-icons.mjs search <word>`), `size`, `color`; valid only in a hand-drawn scene (`references/sketch.md`) | opacity (a drawn scene refuses keyframes) |

Group: `children` are ordinary elements (any type, a group too, up to 3 groups deep) whose `x` and `y` are measured from the **group's centre**, not the canvas: a group at `x: 960, y: 540` with a child at `x: 0, y: -100` puts the child at 960, 440. The group's `opacity`, `scale` and `rotate` act on all its children at once (scale and rotation turn about the group's centre), and its `x`/`y` keyframes move them together; each child keeps its own keyframes on top. A child's keyframe `t` is still seconds inside the scene. `id`s are unique across the whole spec, children included, and a validator problem in a child names its nested path (`scenes[0].elements[2].children[1].text`). `check.mjs` judges the children, not the group. A group fade is drawn as one layer, so it can differ from fading each child by one level per colour channel.

Video: real footage in a scene. The clip plays from `trimStart` to `trimEnd` starting `offset` seconds into its scene; before that it holds its first frame, and once the trimmed range ends it holds its last frame until the scene ends. It is timed by its own scene only (a scene change hides it like any element; under a `crossfade` into the next scene it stays frozen on its last frame of its own scene). Validation needs `ffprobe` (it ships with ffmpeg): it reads the clip's length, so `trimEnd` past it (`trimEnd 12 exceeds the clip length 8.5s`) and `trimStart` not before `trimEnd` (`trimStart must be less than trimEnd`) are errors; without ffprobe a spec with a video gets one error naming `doctor --fix ffmpeg`.
**Render and check** decode the trimmed range once with ffmpeg (`-ss trimStart -to trimEnd`, `fps=<render fps>`, scaled to `width` x `height` by `fit`) into a frame cache, and the page shows frame `round((scene time - offset) × fps)` (held at the first and last) as an image, so every frame is exact and two renders of the same spec and clip are byte-identical. The frames are JPEG at the highest quality (PNG when the clip has an alpha channel, which includes a VP9 WebM with alpha such as `cutout.mjs` writes: it says `yuv420p` and carries the alpha as side data, so ffmpeg is told `-c:v libvpx-vp9` to decode it), so the MP4 stays close to the source (measured on the 320x180 test clip in `test/video.test.mjs`: about 52 dB PSNR between the MP4 and an independent decode of the source).
The cache lives in `<skill-dir>/.cache/video/<key>/` (gitignored), one folder per clip, keyed by the clip file's SHA-256, `trimStart`, `trimEnd`, the fps, the size, `fit`, alpha, the ffmpeg version and a cache format version, so a changed clip, field or ffmpeg decodes again and an unchanged one never does. A folder counts only when its `done.json` names a whole decode (a positive frame count, with the first and last frames present); anything else is decoded again. ffprobe and ffmpeg open clips and audio files through the `file` protocol only (`-protocol_whitelist file,pipe`), so a playlist renamed to `.mp4` cannot fetch anything.
It grows with every new clip and size; `node scripts/doctor.mjs` lists it once it passes 2 GB, and `node scripts/doctor.mjs --fix cache` deletes it (any time; the next render decodes what it needs). The frames are decoded at the element's `width` x `height` in canvas pixels, so a `scale` keyframe above 1 or `render --size` larger than the spec's size enlarges them. **Sound:** unless `mute` is true, the clip's audio joins the mix like an `audio` track, from the moment it starts playing, at `volume`, for the trimmed length, and stops when its scene ends (the clip leaves the screen then, so its sound never plays over the next scenes); a clip without an audio stream adds nothing. **Preview** plays the clip itself in a muted `<video>` seeked to `trimStart + (scene time - offset)`: it is approximate (the nearest decodable frame, and it can lag while playing) and silent; the render is the exact one. Contact sheets and `check.mjs` use the decoded frames too, so they need ffmpeg as well.

Lottie: an After Effects animation exported as Lottie JSON (Bodymovin, LottieFiles), played inside the element's box. Its frame at scene time `t` is `clamp((t − offset) × speed × fr, 0, floor(op − ip) − 1)` counted from the file's in point (lottie-web counts from `ip` rounded to a whole frame; `fr`, `ip`, `op` are the file's frame rate, in point and out point): it holds its first frame before `offset` and its last frame (one before `op`: at `op` itself the layers that end there are gone) once it has played, until its scene ends. Sub-frames are drawn, so a 30 fps file in a 60 fps render moves on every frame. The element's own `keyframes` move, scale, turn and fade the whole animation; nothing inside the file is animatable from the spec.
`offset` and `speed` are plain numbers (a `{{name}}` var works; `"beat:<n>"` does not: it times keyframes and cues only). The page plays it with lottie-web's light SVG build, which has no expression engine; the server serves that one file of the package and nothing else of it, and the page's CSP has no `unsafe-eval`. The file is untrusted, so the validator and the page both check it before lottie-web sees it (`template/lottie-guard.mjs`): at most 4 MiB, nested at most 128 levels, at most 200 assets, read with own-property lookups only (a leading byte-order mark is allowed). Every asset is checked: a precomp (an asset with `layers`) must hold an array there and name no file (`assets[0].u: a precomp names no file; remove u`).
An image asset must be embedded as a PNG, JPEG or WebP data URL (`assets[2].p: remote assets are not allowed; embed the image as a data URL`; an `svg+xml` or any other data URL: `only PNG, JPEG or WebP images can be embedded`), and so must an image slot; a data asset (`t: 3`), external `segments`, a font with an `fPath` or an `fOrigin` other than `"n"` (`fonts.list[0].fPath: remote fonts are not allowed; use a system font (fOrigin "n", no fPath) or embed the glyphs (chars)`) and an expression (`layers[0].ks.p.x: expressions are not supported`: a non-empty string `x` on any object with a `k`, so a property with or without `a` and a text document `t.d`, or on a slot's value `slots.<id>.p`; a string `x` on a layer or the root is left alone) are refused, as is a `__proto__` key.
A tiny file can still ask lottie-web for so much drawing that the page stops, so what it builds is capped too (`template/lottie-budget.mjs`): a repeater's copies at 1,000 (`layers[0].shapes[1].c: 200000 repeater copies; at most 1000`), zig-zag ridges and star points at 1,000, gradient stops at 256, a text document at 20,000 characters, and every layer and shape, with repeaters, precomps and glyphs multiplied out (a precomp once per layer that uses it, the largest glyph once per character of a text layer's longest text), at 10,000 (measured on this machine: a file at that cap is ready in about 0.35 s); a precomp that contains itself and a `refId` that names no asset are refused by name.
A keyed count is capped at the largest value it really takes: a bezier ease whose `y` handles leave 0 to 1 overshoots its keys (keys 1 and 1000 with `y` 400 reach about 300,000 copies), so the maximum over each keyframe's ease is solved exactly (a hold keyframe jumps and is not eased). Values lottie-web writes into the page as they are must be plain: a solid layer's `sc` a `#rgb` or `#rrggbb` colour (`layers[0].sc: must be a colour like #ff0000 (a solid layer's fill)`: a `url()` there would be a fetch), `sw`, `sh`, a layer's or an asset's `w` and `h` numbers, an image's `pr` a preserveAspectRatio value, and a font's `fName`, `fFamily`, `fStyle` and `fWeight` plain names (letters, digits, spaces and `. , ' - _`).
As a backstop for whatever these checks miss, `render.mjs` (the video, every `--workers` page and the contact sheet) and `check.mjs` hold the page to two time limits measured in Node, where a page whose main thread is stuck cannot stop them: at most 30 s plus 5 s per element that loads something (image, video, chart, code, lottie; 300 s at most) to build its stage (`the page did not become ready within 35 s (any page error is printed above); a lottie file too heavy to draw stops the page: "badge" (data/badge.lottie.json)`), then at most 10 s for each seek and each screenshot (`the frame at 1.2 s (frame 36) did not finish drawing within 10 s; a lottie file too heavy to draw stops the page: …`); the browser is closed, and a render that stops leaves no MP4 and no contact sheet behind.
A file that makes lottie-web run out of stack fails with `lottie anim.json is too complex for lottie-web to draw (it ran out of stack: …)`. Preview opens the page in your own browser, so only the checks above protect it. A layer's or shape's `ln` and `cl` and a font's `fClass` would become ids and classes in the page, so the page removes them before lottie-web sees the file; the file draws the same without them. A file missing `v`, `fr`, `ip`, `op`, `layers`, `w` or `h` is `not a Lottie file (missing fr)`.
The validator reports these at the element's `src`, naming the file (`scenes[0].elements[0].src: assets[2].p: remote assets are not allowed; embed the image as a data URL (in data/badge.lottie.json)`), five at most and a count of the rest; a `.lottie` archive is refused with `export the animation as Lottie JSON (.json)`. A text layer draws with a system font (or the file's embedded glyphs), so its look can differ between machines; shapes and embedded images do not. `grade` is not valid on a lottie. `check.mjs` counts a lottie that is still playing as change for the dead-stretch audit (its frame is part of what it compares). Two renders are byte-identical, at any `--workers` (measured in `test/lottie.test.mjs`, with an embedded PNG, a fade, a camera and keyframes). Example: `references/examples/lottie-badge.json` (the badge, `references/examples/data/badge.lottie.json`, is a 2 s shape animation written by hand for this repository: CC0).

Grade: `"grade": { "preset"?, "exposure"?, "contrast"?, "saturation"? }` on an `image` or a `video` (any other type is `grade: only valid on image or video elements`) colours the picture, not the element's box, so the element's own `opacity`, `scale`, `rotate` and `keyframes` act on the graded picture as before. `preset` is `warm`, `cool`, `mono` or `film`; `exposure` is in stops (−2 to 2, default 0; the picture is multiplied by 2^exposure), `contrast` 0.5 to 2 (default 1; it pivots on mid-grey, so 128 stays 128), `saturation` 0 to 2 (default 1). All three work without a preset. A grade that changes nothing (`{}`, or every number at its default and no preset) is an error that says what to set, and a value outside its range names the limit (`grade.exposure: must be <= 2`).
A grade is not animatable: a keyframe cannot carry it. It is one SVG filter in the sRGB colour space (the 0–255 values a viewer sees), applied in this order: saturate by `saturation` × the preset's; the preset's colour matrix (warm and cool); then one linear step on red, green and blue with slope 2^`exposure` × `contrast` × the preset's contrast and intercept 0.5 − 0.5 × that contrast; then the preset's black lift (film).
The presets: `warm` multiplies red by 1.08 (+0.02), green by 1.02 and blue by 0.9 (−0.02); `cool` multiplies red by 0.92 (−0.02), blue by 1.1 (+0.02); `mono` is saturation 0 whatever `saturation` says, with contrast × 1.1; `film` is saturation × 0.85, contrast × 1.15 and a table lift on each channel (`tableValues="0.06 1"`) after the linear step, so the floor holds at any exposure or contrast (measured through the page on greys: 0 reads 15, 128 reads 135, 255 stays 255). The page holds one `<svg><defs>` on the stage with one `<filter>` per graded element, named `grade-0`, `grade-1` and so on in document order: an element's own `id` never reaches the markup or a CSS `url()`.
The filter sits on the `<img>` or `<video>` inside the element, outside every node the page renews, and adds no `will-change` in a render, so two renders of a graded spec are byte-identical, at any `--workers` (measured for an image and for a video in `test/grade.test.mjs`). `check.mjs` and the contact sheet screenshot the page, so a text over a graded photo is judged on the graded pixels. Example: `references/examples/graded-photo.json` (with `photo.png`, a landscape drawn procedurally for this repository: CC0).

Anchor (text only): `"anchor": "left" | "center" | "right"` (default `center`) says which edge of the text box sits on `x`: `left` puts the left edge there (the box grows rightwards), `right` the right edge, `center` the middle as before. `scale` and `rotate` turn about that edge (`transform-origin` is `left center` or `right center`), so a scaled or typed left-anchored line keeps its left edge fixed. Three stacked lines of different lengths with one `x` and `"anchor": "left"` share a left edge. `anchor` does not change `align`, which still aligns the lines of one wrapped box inside it. A text with no `anchor`, or `"center"`, renders exactly as before. On any other element type `anchor` is an error (`scenes[0].elements[0].anchor: not valid on shape; allowed: …`); a counter has no `anchor`.
`check.mjs` warns (stderr `warning: scenes[0].elements[1]: text "b" nearly lines up with "a": left edges differ by 5 px`, under `warnings` in `--json`; exit and `errors` unchanged) when two texts in one scene that say `"anchor": "left"` or `"align": "left"`, both on screen and not moving, have left edges more than 0.5 and up to 12 px apart at 1080 on the short side (scaled with the canvas: 6 px at 540, 24 px at 2160). 0.5 px or less is aligned and 13 px or more reads as a different column, so neither warns. Texts that state no left intent (centred or unstated `align` with the default anchor, or `right`) are never compared, since a centred line's left edge follows its width and two of them land a few px apart by chance; stacked `"align": "left"` lines with the default centre anchor stagger by their widths, which is what the warning catches. Parts of a block are not compared: a block's layout is not the author's to fix.

Title role: a `text` with `"role": "title"` uses the theme's display font (the weight maps to the one the display font ships). `"font": "mono"` wins over the role: a mono title draws in the mono font, still with the entrance preset below. When it has **no** `keyframes` it gets the theme's kinetic entrance: `dusk` **rise** (fades in and rises 0.35 × `fontSize` into place, 0.9 s), `press` **ink-in** (fades in while settling from 104% scale, no movement, 1.1 s), `poster` **slam** (snaps in from 135% scale with an `outBack` landing, 0.5 s). A preset is a plain function of the scene duration and `fps`, compressed to end at least one frame before a short scene's end, so renders stay reproducible. Any `keyframes` (an empty list too) turn it off. `paper`, `ink`, `blueprint` and `editorial` have no preset.

Exit (opt-in): `"exit": true` on such a title also gives it the theme's exit, with the `exit` ease: `rise` fades as it drops 0.35 × `fontSize`, `ink-in` fades as it grows back to 104%, `slam` fades as it snaps down to 85%. The exit takes half the entrance (0.45 / 0.55 / 0.25 s) and lands one frame before the scene end, but never starts before 90% of the scene (a shorter scene gets a shorter exit, so the 85% contact frame always shows the title fully in). It is skipped on the spec's last scene, when the entrance has not landed by 90% of the scene, and whenever the title has its own `keyframes`. Without `exit` nothing changes.

Typing (opt-in): `"typing": true` on a `text` reveals its characters one at a time, 0.035 s each, from the start of its scene, with a caret after the last typed character (a thin bar; solid while typing, blinking every 0.5 s once the text is complete). Counted in grapheme clusters, so an emoji, a ZWJ sequence, a flag or a letter with a combining accent is one character and is never typed in halves. The element's box is always the full text: the untyped rest keeps its space but is not drawn, so a centred line does not shift as it fills and `check.mjs` judges its final box from the first frame.
Its animatable `value` is the number of characters typed: with no `value` keyframes it runs 0 → N from t=0 at 0.035 s per character; add any `value` keyframe to take control of the start and pace (as on a counter's `value`). `typing` on any element type but a text or a code element is an error, and so is a `value` keyframe on a text without it. A typing text with no `value` keyframes must finish a frame before its scene ends (`0.035 × characters + 1/fps` seconds at most) and by the last frame the render draws of its scene, or the validator says to shorten the text or lengthen the scene to a length it names, one that passes. The render draws `round(total × fps)` frames at `i / fps` (a frame on a scene boundary is the next scene's), so a scene's last frame can come up to 1.5 frames before its end; the same rule holds for typing code and for the blocks with a schedule (`code-typing`, `terminal-run`, `listicle`, `story-beats`, `before-after-swipe`).

Code: highlighted source code in the theme's mono font, left-aligned in a box `width` wide, one row per line (a long line wraps at any character inside the width, so the box never grows sideways). It is highlighted once at load with [shiki](https://shiki.style) (MIT): its fine-grained core, its JavaScript regex engine (no WebAssembly) and only the grammars the spec's code elements name, all served from the skill's own `node_modules`, so nothing is fetched. Colours come from the theme's dark tokens: keywords `accent`, strings `good`, comments `text3`, numbers and constants `warn`, functions `cat1`, types `cat2`, everything else `text`; the background is transparent. Each `highlight` line gets a `surface` row behind it.
With `"diff": true` a line starting with `+` gets a `good` tint (15 %), one starting with `-` a `bad` tint, and that first character is drawn as a marker, the rest highlighted as `lang`. `typing` types the code exactly as a text types (0.035 s a character, newlines counted, the caret moving row to row; the box is the whole code from the first frame), with the same rule: no `value` keyframes means it must finish a frame before the scene ends (`scenes[0].elements[0].code: typing 100 characters takes 3.50s … shorten the code or lengthen the scene …`). The code is drawn as text, never as markup: `<script>` in it is just those characters.
An unknown `lang` names the closest one (`scenes[0].elements[0].lang: unknown lang "js"; did you mean "javascript"? (langs: text, javascript, …)`), and a `highlight` past the end says how many lines there are (`highlight[1]: line 5 is past the end; the code has 3 lines`). `check.mjs` judges a code element like a text: safe area, overlap, caption zone, text floor (28 px at 1080, so the default size passes exactly) and contrast, where every token colour is judged against the backdrop and the worst one reported.

Counter default: a counter with **no** `value` keyframes counts `from` → `to` from t=0 to `min(2, 0.8 × scene duration)` seconds with `outCubic`. Add any `value` keyframe to take control of the timing.

Colours (`background`, scene `background` other than `"art"`, `color`, `fill`, `stroke`) must be hex (`#rgb`, `#rrggbb`, with optional alpha), `rgb()/rgba()/hsl()/hsla()` or a named CSS colour. `url(...)`, `var(...)` and anything else is rejected.

Theme colour tokens: a shape `fill` or `stroke` and a text or counter `color` may also name a token (`surface`, `line`, `accent`, `accentSoft`, `good`, `bad`, `warn`, `text`, `text2`, `text3`, `cat1`..`cat6`) instead of a hex. It resolves to that colour of the active theme's dark variant, so a theme change recolours the card too. Backgrounds take no tokens; an unknown name is an error that lists them. Hex specs render exactly as before.

Shape notes: a `line` has length `width`, thickness `strokeWidth` and is horizontal; angle it with `rotate`. To grow a vertical bar upward from a baseline, use a line with `"rotate": 270` and animate `draw` 0→1. `fill` defaults to the theme accent for rect/ellipse unless only a `stroke` is given. `"elevated": true` on a rect draws a card: the fill moves 6 % toward the theme text colour and a 1 px `rgba(255,255,255,.06)` highlight sits just inside the edge (no drop shadow, which would not show on a dark page); it is drawn as one extra node after the rect, is drawn in with it as `draw` grows, and is left off a rect with only a `stroke` (no fill to lift). `"elevated": false` is accepted on any shape and does nothing.
`"cap": "round"` rounds a line's ends and pulls both endpoints in by half the stroke width, so the line keeps its `width`; the default stays flat. A round-cap line stays hidden until its drawn length is more than a cap radius (half the stroke width), so it grows from a stub rather than popping in as a dot. A line with an arrow needs a `width` of more than 3 × `strokeWidth` (3.5 × with a round cap) and one with a round cap alone more than `strokeWidth`; the validator names the minimum. `"arrow": "end"` adds a filled triangle head (3 × `strokeWidth` long, 3 × wide, ending at `width`) that appears once `draw` reaches 0.98.

Chart notes: data must be inline: `data.values`, or `datasets` plus `data: {name}`. Any `url` key anywhere in the Vega-Lite spec (remote `data.url`, lookup `from.data.url`, image-mark `url`) is rejected; the renderer also blocks all non-local network requests. Do not set `width`/`height` inside `vegaLite`; the element's are used. The theme's fonts, axis colours, accent and palette are applied through a built-in Vega-Lite `config`; your own `config` keys override it. The built-in config also sets: about five ticks on each axis, no y domain line, no tick marks and no vertical gridlines, bars with 10 px rounded ends and a 0.3 gap between them, lines 4 px wide with round caps and joins, and filled points ringed in the page colour (a hollow `filled: false` point keeps its accent outline). The chart `reveal` is a left-to-right wipe with a soft edge. The chart is rendered to SVG once at load.

Maps: `data: { "name": "<atlas>" }` draws one of four bundled atlases (pinned world-atlas 2.0.2 and us-atlas 3.0.1, ISC; nothing is fetched from outside, the page reads the file from `/vendor`): `world-110m` (177 countries, the one to use), `world-50m` (241, finer coasts, 0.7 MB), `us-states-10m` (the 50 states, DC and five territories) and `us-counties-10m` (3,231 counties; their names repeat across states, so join on `id`, the 5-digit FIPS code). No `datasets` entry is needed (one of the same name wins). Each feature has `properties.name` (and an `id`); draw them with a `geoshape` mark and a `projection` (`equalEarth` for the world, `albersUsa` for the US, which also tucks Alaska and Hawaii under the lower 48; a place albersUsa cannot draw, such as Guam, is left out).
Join your numbers to the shapes with a `lookup` transform on `properties.name` whose `from.data.values` holds the rows (`{ "lookup": "properties.name", "from": { "data": { "values": [{ "state": "Texas", "orders": 4100 }] }, "key": "state", "fields": ["orders"] } }`) and colour with `encoding.color`. A mark's `fill`, `stroke` or `color` may be a theme colour token (`surface`, `line`, `accent`, `text`, `text3`…): `"fill": "surface"` is the theme's surface colour, resolved on the page.
A name that is neither a `datasets` entry nor an atlas is `vegaLite.data.name: dataset "x" not found in vegaLite.datasets; bundled maps: world-110m, world-50m, us-states-10m, us-counties-10m` (with `did you mean` for a near miss); the validator compiles the chart with the real atlas file, so a projection or encoding error surfaces at validate. `references/examples/world-map.json` is a world scene with some countries lit and a US choropleth; the `map-highlight` and `flow-map` blocks (below) draw the common cases from a few params.

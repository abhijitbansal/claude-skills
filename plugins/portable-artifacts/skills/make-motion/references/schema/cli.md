# motion.json reference: the command line: every script and its flags

Part of the reference indexed in ../schema.md.

## CLI
Every script answers `--help` (or `-h`) with its usage on stdout and exit 0; an unknown flag is exit 2 with the usage line, `validate.mjs` and `preview.mjs` included. Run each as one plain command with its literal path.
- `node scripts/validate.mjs <spec> [--json]` — exit 0 / 1 / 2; with `--json` a usage error is `{ "ok": false, "errors": [...] }` on stdout, as in the other skills.
- `node scripts/blocks.mjs list` / `node scripts/blocks.mjs show <name>` — the blocks and their params (see Blocks). Exit 0, or 2 for an unknown command or block (`unknown block "kpi"; did you mean "kpi-counter"? (blocks: …)`).
- `node scripts/voice.mjs "<text>" | --text-file <file> --out <file.wav> [--voice af_heart] [--speed 0.5–2] [--phonemes]` / `--dir <folder> [--voice af_heart] [--speed 0.5–2]` / `--list-voices` — `--list-voices` prints a static table (28 voices: name, language, gender, grade) and loads no model, so it downloads nothing. `--dir` makes every `.txt` in the folder into `<name>.wav` plus `<name>.json` beside it on one model load, one stdout line per file (`<wav><TAB><seconds> s, <voice>`, or `<wav><TAB>unchanged` for one whose text, voice and speed match the `textHash` its sidecar records; with nothing to make the model never loads); it refuses `--out`, `--phonemes`, a text argument and `--text-file`. `--help` prints the usage on stdout and exits 0.
  The first run's model download prints one line per file on stderr (`voice: downloading the Kokoro voice model file … (once) from <url>`). Synthesises a voiceover locally with Kokoro (kokoro-js, Apache-2.0; 24 kHz mono wav; prints the wav path, the duration and the sidecar path; with `--phonemes` it then prints one `<sentence><TAB><phonemes>` line per sentence; also writes `<file>.json` beside the wav with `{ sampleRate, voice, sentences: [{ text, start, end, phonemes }] }`, times in seconds from the clip start, `phonemes` the Kokoro phoneme string for that sentence).
  Needs `npm ci --ignore-scripts --prefix <skill-dir>/optional/voice` (on demand, from that folder's lockfile, install scripts skipped; not part of the skill's `npm ci`, which leaves it alone; the doctor's `--fix kokoro` runs the same step; about 440 MB) and a one-time ~90 MB model download, pinned to one Hub commit with each file checked against its SHA-256, into a per-user folder (`$CLAUDE_PLUGIN_DATA/models`, else the OS cache folder such as `~/Library/Caches/portable-artifacts/models`, else `<skill-dir>/.cache/models`) so a plugin update does not fetch it again; offline after that. Exit 0 / 2 usage or not installed / 1 synthesis error.
- `node scripts/cutout.mjs <photo.png|clip.mp4> [--out <dir>] [--fps n]` — cuts the person out of a photo (writes `<out>/<stem>.png`, RGBA) or a clip (writes `<out>/<stem>.webm`, VP9 with alpha, no sound; `--fps` 1–60, default the clip's own rate up to 30; at most 900 frames) with MODNet (Apache-2.0) on onnxruntime-node (MIT), locally; `<out>` defaults to a `cutout` folder next to the input, and the input is never overwritten. Prints the path written. A photo or a frame is shrunk to MODNet's size (short side 512), matted, and the matte enlarged back; decode and encode go through a Chromium canvas. The alpha frames of a clip are kept in `<skill-dir>/.cache/cutout/<key>/` (keyed by the clip's SHA-256, the rate and the weights), so rerunning the same clip only encodes.
  Pass the original as `src` and the file it prints as `cutout` of a `text-behind-subject` block. Needs `npm ci --ignore-scripts --prefix <skill-dir>/optional/cutout` (on demand, from that folder's lockfile, install scripts skipped; not part of the skill's `npm ci`; `doctor --fix cutout`; about 300 MB) and a one-time 25 MB download of the weights (commit-pinned Hugging Face URL, checked against a SHA-256 before every use) into `modnet/` under the same per-user models folder as the voice model (see voice.mjs; `<skill-dir>/.cache/models/modnet` where there is no home folder); offline after that. A picture over 8192 px on a side or 64 MB is refused from its header, before a page decodes it. `doctor --fix cache` clears `.cache/video` and `.cache/cutout`, never the models. The voiceover and cutout installs live in their own folders, so neither removes the other. Exit 0 / 2 usage or not installed / 1 failure.
- `node scripts/beats.mjs <audio> [--out <file>.json] [--min-confidence 0.5] [--bpm <n> | --min-bpm <n> --max-bpm <n>]` — finds the beat grid of an audio file and writes `<audio-stem>.beats.json` for a spec's root `beats` (see Beats). Prints the path and `<bpm> BPM, <n> beats`. Exit 1 when no steady beat is found (`no steady beat found in music.wav (confidence 0.31; needs 0.5)`) or ffmpeg cannot decode the file; exit 2 for a usage problem: an unknown option (the accepted ones are listed), a path starting with `-`, an unreadable file, a tempo flag out of range or combined wrongly (`--bpm` with `--min-bpm`), or an `--out` that is the audio, a folder, a symbolic link, not a `.json` file or an existing file that is not a beats file. `--bpm <n>` forces the tempo and `--min-bpm`/`--max-bpm` narrow the search (see Beats). Needs ffmpeg.
- `node scripts/preview.mjs <spec> [--open]`
- `node scripts/check.mjs <spec> [--json] [--theme name]` — seeks the render page to every contact-sheet moment (all of them, uncapped); flags a visible text or counter outside the safe area (60 px at 1080 on the short side, on every side: 60 px at 1920x1080, 120 px at 3840x2160) while it is not moving (between or after its keyframe tweens), two visible texts or counters overlapping while neither is moving or fading, and a scene that ends with nothing on screen (every element invisible or wholly off the canvas; a title whose `exit` preset was applied counts as present, since it left on purpose).
  With `captions`, also a visible text or counter whose box reaches into the caption zone while it is not moving and a caption is on screen (`scenes[0].elements[1]: text "sub" sits in the caption zone (y >= 842) at 1.00s; move it above y 842 or end the captions before it`; with no caption showing, the lower band is free; judged at the sheet moments and at every caption group's midpoint), and a captions layer that leaves the zone (`captions[0]: captions leave the caption zone (right) at 1.40s`, video time). Each layer is measured once per caption group, at its midpoint (and for `kinetic` at each word's start, where the pop is largest), as the box around the layer and every word, so transforms and the pop count.
  A **warning**, never a failure (exit stays 0; printed to stderr as `warning: scenes[0]: ...`, and under `warnings` in `--json`, which is left out when there is none), when the first scene shows nothing at t = 0, since that blank frame is the video's thumbnail (not when something is on screen at half opacity or more by the second frame, a blink and not a blank opening); the message names the cause (a `fade`, an opacity 0 first keyframe such as a title's theme entrance, a line or chart at `draw`/`reveal` 0, or a typing text or code element with no characters typed yet: its caret alone is not content). An `art` background counts as shown.
  Another warning: two texts of a scene that say `"anchor": "left"` or `"align": "left"` (not block parts), on screen and not moving, with left edges more than 0.5 and up to 12 px apart at 1080 on the short side (`text "b" nearly lines up with "a": left edges differ by 5 px`; see Anchor). A scene is judged where it settles, never where a `push`, `slide`, `zoom`, `wipe`, `blur` or `iris` window has moved, clipped or blurred it.
  Each transition window is sampled at its midpoint, with both layers drawn as they are, and a visible text or counter of the incoming scene that overlaps one of the outgoing scene there is a warning too (`warning: scenes[1].elements[0]: text "b" overlaps text "a" of the outgoing scene "a" during the crossfade at 2.20s; ...`; a `push` moves the layers apart, so it has none). A box wholly off the canvas has left the frame and is never clipped. A scene `camera` is part of the box (boxes are read after it), and a camera tween counts as every element of the scene moving, (see Camera).
  Four audits sample every scene on a 0.25 s grid (and the colour behind each text at the sheet moments): **contrast**, WCAG AA of a text's or counter's colour (a `code` element's worst token colour) against the pixels behind it (4.5:1, or 3:1 for large text: 24 px at 1080 on the short side, or 18.67 px at weight 700 or more). The text is made transparent and one screenshot read, so the art-background plate counts as backdrop; the text box is split into up to 4 x 2 cells and the worst cell is judged, with the colour blended at its alpha (`rgba(255,255,255,0.15)`) and the element's opacity. A text inside an opacity tween of its own or a group's is skipped at that moment.
  `scenes[0].elements[1]: text "sub" has 2.1:1 contrast against its backdrop at 0.10s; needs 3:1; nearest passing token: bad` (the first of `text`, `text2`, `text3`, `accent`, then the other colour tokens that passes over every cell; when none does, `no single colour passes over this background; add a backing card (fill "surface") or move the text`); **reading floor**, a `text` stays on screen for 0.75 x (0.5 + 0.3 x words) seconds (7 words need 1.95 s, the last line included; a text is reported when its measured time on screen is more than one 0.25 s step short, the edges of a borderline span being measured with extra page reads; the need is printed rounded up; a last line still shown at the final frame for under 2 s that clears the formula gets an **info** line instead,
  `info: scenes[0].elements[1]: text "bye" (1 word) shows for 1.50s; a last line reads best at 2 s or more`, printed on stderr and under `info` in `--json`, never changing the exit code), `text "sub" (7 words) shows for 1.25s; needs 1.95s`; **dead stretch**, more than 3 s in which nothing on screen changes (an element's position, size, opacity, text, drawing, reveal, value or video frame, a caption, a scene cut, a transition window), except in the last 3 s of the video and while only `hold` elements are on screen, `scenes[0]: nothing changes from 4.00s to 7.50s (3.5s); add motion, such as a slow camera push-in, or set "hold": true on text "a", rect "panel" if they are meant to sit still` (only elements that are shown count, so an invisible or off-canvas drifting element hides nothing;
  the message names the shown elements without `hold`, and a block once as `block "lt"` rather than its parts, since `hold` goes on the block); **text floor**, a `text`, `counter` or `code` drawn under 28 px at 1080 on the short side (scaled by the canvas, by `scale` and by a scene camera's zoom) for 0.5 s or more while its own size is not tweening (a camera zoom tween does not relax it), `text "fine-print" is 22px (below 28px at 1080); shown 1.50s`. A contrast or text-floor finding at a single sampled moment is a **warning** (stderr, exit stays 0), at two or more consecutive moments a problem; reading floor and dead stretch are always problems.
  Captions are not elements, so the reading floor and text floor never judge them (their timing comes from the transcript), though a caption change counts as change for the dead-stretch audit. A finding inside a block names the block, the part and what to change (contrast: `blocks use theme colours; change "theme" or the scene background`, or when no colour passes `no theme colour passes over this background; change "theme" or the scene background`; text floor: `raise the block's "scale" or use a larger format`; reading floor: a longer scene or a shorter param).
  The contrast audit reads no backdrop inside the window of a transition the scene comes in through (any type, `crossfade` included: the screenshot is two layers there; and a `fade`'s, where the scene is half faded in), so a text is judged at its later moments; a text whose every shown moment falls inside its window is not judged at all and gets `info: scenes[1].elements[0]: text "x" was not judged for contrast: every moment it shows in falls inside the push window of its scene; lengthen the scene or shorten the transition` (printed on stderr and under `info` in `--json`, never changing the exit code). `--theme` is the theme for a spec that sets none, as in render.mjs (an unknown name exits 2). A crash prints `check crashed: …` alone (JSON `crashed: true`).
  Exit 0 ok (or `check: skipped (no browser: …)`), 1 problems, 2 usage. With no browser (or `PA_NO_BROWSER=1`) a hand-drawn scene's stroke plan is still judged, so a voiced drawing that cannot fit its narration even at twice the pace is a problem (exit 1, with a warning that the page audits did not run); every other spec skips as before.
- `node scripts/render.mjs <spec> [--out file.mp4] [--fps n] [--size WxH] [--theme name] [--model m] [--effort e] [--agent a] [--workers n|auto] [--quality draft|final] [--loudness <lufs>|off] [--true-peak <dbtp>] [--no-provenance] [--contact-sheet] [--poster <seconds> [--poster-out <file>.jpg|.jpeg|.png]]` — `--poster <seconds>` writes one still of the film's frame `round(seconds x fps)` and no MP4: the page is seeked as for the video, the `#stage > .captions` layers are set to `visibility: hidden`, and the screenshot is taken (so a block laid out above the caption zone keeps that layout, and grain and vignette stay).
  The default path is `<specdir>/out/poster.jpg` (JPEG quality 92); `--poster-out` names another file, whose extension (`.jpg`, `.jpeg`, `.png`) picks the format, and it may not be a file the render reads (`--poster-out: pic.png is a file this render reads (pic.png); choose another --poster-out`, exit 2). A frame inside a GL transition window is composed as in the video. The path is printed (second line `poster: frame N @ F fps, WxH`).
  Exit 2: `--poster-out` without `--poster`, a time that is not a number of seconds, a time past the end (`--poster 40: past the end (the video is 3 s)`; the frame must exist, so the video's own length is past the end), any other extension, and `--out`, `--batch`, `--contact-sheet`, `--workers`, `--loudness`, `--true-peak`, `--no-provenance`, `--model`, `--effort` or `--agent` with `--poster` (each message names the flag and what to do). A time that rounds onto a frame past the last one (`--poster 6.99` on a 7 s video at 24 fps) exits 2 with the frame count: `--poster 6.99: past the end (the video is 7 s, 168 frames, last frame 167)`. `--quality draft` works and gives a half-size poster.
  `--no-provenance` (or a root `"provenance": false`) writes the MP4 without the `comment` and `artist` tags, on the plain encode and through the `--loudness` second pass alike; `--no-provenance --contact-sheet` exits 2. This removes the authoring tags. ffmpeg's own encoder tag stays. `--workers` (an integer 1–16, or `auto` = max(1, min(8, cores − 1)); the default is `auto`, and the `workers: N` note on stderr appears only when you pass the flag) captures frames on that many pages of one browser (never more pages than frames): the pages take the next frame in turn and ffmpeg receives the frames in order.
  A frame's bytes do not depend on which page drew it or on which frames were drawn before it, so the MP4 is byte-identical to `--workers 1`; audio is mixed once after the frames as before, and a page that fails stops the render with `worker <k> failed at frame <j>: <message>` (k counts from 0; exit 1, no partial MP4). Frames wait as PNG files in a temp folder outside the spec folder, removed on every exit. A page never runs more than 2 frames per page ahead of the encoder, so at most 2 × workers PNG files exist at once (8 workers: 16 files, about 0.5 MB at 1080p for a flat design, about 10 MB with film grain) however slow the encoder is.
  Each page is a full copy of the stage in memory, and a scene with `texture.grain` holds a full-frame grain bitmap on each page, so memory grows with `--workers`: at 4K with grain and many scenes, keep it low (`auto` is capped at 8). `--quality draft` renders at half the size on each side (rounded down to even, never under 16; 1920x1080 gives 960x540) with `-crf 30 -preset veryfast`: the page itself is that size, so captions, the safe area and fonts shrink with it; `final` is the default and changes nothing. `workers: N` (only when N is above 1) and `quality: draft (WxH)` go to stderr; stdout is the same either way.
  An unknown value (`--workers 0`, `--workers 17`, `--quality fast`) exits 2 and lists the accepted ones, as do `--quality draft --contact-sheet` and `--workers <anything> --contact-sheet` (a contact sheet is always full size, on one page, whatever the core count). `--model`/`--effort`/`--agent` override the spec's `generatedBy` (hostile values fail validation, exit 1); `--theme` is a shared theme for a spec that sets none (a spec's own `theme` wins; an unknown name exits 2).
  Default out `<specdir>/out/<name>.mp4`; an `--out` that is a file the render reads (the spec, or a clip, image, sound or captions file it names) exits 2 before anything is written (`--out: clip.mp4 is a file this render reads (footage/clip.mp4); choose another --out`); with `--contact-sheet`, `--out` is a directory and PNGs go to `<out>/contact/<scene-id>.png` (default `<specdir>/out`). A hand-drawn scene's sheet also has a tile just after each element finishes drawing and tiles at 25, 50 and 75 % of the way through the drawing (from the first stroke to the last), so the sheet shows the board part-drawn and not only blank then finished; past 11 moments the three drawing tiles are kept and the landings are picked evenly. `--size` sides must be 16–3840 and even.
  Output is written to `<name>.partial.mp4` and renamed on success; Ctrl+C removes it (exit 130/143). `--loudness <lufs>` (−30 to −5) normalises the mix to that integrated loudness and `--true-peak <dbtp>` (−3 to 0) sets the true-peak ceiling (−1.5 when neither the flag nor the spec's `loudness` gives one); without a flag the spec's root `loudness` is the target (viral mode sets −14 / −1), a flag winning field by field, and `--loudness off` turns normalising off even when the spec sets one.
  After the encode (into `<name>.partial.mp4`), a first `loudnorm` pass (`I`, `TP`, `LRA=11`, `print_format=json`) measures the mix and a second copies the video stream and re-encodes the audio through a linear-mode `loudnorm` with those measurements (AAC 48 kHz stereo 192 kb/s as before) into a second temp beside it (`<name>.partial.loudnorm.mp4`), capped at the clip length (`-t`) as the first encode is, so the audio is not a frame longer than the video; that temp is renamed onto the output, and an error or Ctrl+C removes both temps.
  A mix one gain cannot take is told by pass 1: the gain to the target would put its peaks over the true-peak ceiling (`loudnorm` would cap the gain and land short of the target), or its loudness range is over 11 LU (`loudnorm` would fall back to its dynamic mode).
  Then the gain is applied first, a lookahead `alimiter` holds the peaks at the ceiling minus 3 dB (`volume=<gain>dB,alimiter=limit=<TP-3 dB>:level=false:latency=true`), a pass 1b measures that limited signal with the range check lifted (`LRA=50`), and the same linear `loudnorm` finishes it. loudnorm's measure-only passes read a wide-range signal up to 1.4 LU louder than the 48 kHz chain pass 2 runs, so the finished chain is dry-run once and measured with `ebur128` at 48 kHz, and a miss of 0.1 dB or more is corrected with a `volume` after loudnorm (never past the ceiling).
  Measured on the signals tried (cue mixes, and synthetic wide-range piano and stepped-dynamics signals) the result lands within 1 LU of the target under the ceiling and is byte-identical twice; that is a measurement, not a guarantee for every signal. Mixes that take this branch: those of cues alone whose peaks the gain would push over the ceiling or whose range is over 11 LU (a default viral clip, `viral-hook.json` included), and any music or voice track with a loudness range over 11 LU, which used to meet loudnorm's dynamic mode. A tone, music or voice mix that one gain can reach (peak plus gain under the ceiling, range 11 LU or less) never takes it, and its bytes are those of the plain two passes.
  The limiter reduces the peaks by `peak + gain − (ceiling − 3 dB)`; when that is more than 6 dB, stderr says `loudness: the limiter reduces this mix's peaks by up to N dB (more than 6 dB) to reach -14 LUFS; the mix is quiet or peaky for that target, so consider raising its level or lowering the target`. The stage needs ffmpeg 5.1 or later (alimiter's `latency` option and an LRA over 20 first appear there; audio mixing alone still needs 4.4). Whether it can run is asked of the ffmpeg itself, not read from its version: one dry run of the stage's own filters on 0.1 s of silence, once per process (a git build or a wrapper that hides its version is judged the same way).
  On an ffmpeg that fails it, a mix that needs the stage is not given to loudnorm at all (from 4.4 to 5.0 its cap on an input under 3 s is a difference of two amplitudes, fixed in 6.0, which makes a short clip quieter) but a plain `volume` gain, `min(target − input_i, ceiling − input_tp)` from pass 1, so the true peak stays at or under the ceiling and the clip is never made quieter; stderr says `loudness: this mix needs the limiter stage to reach the target, which needs ffmpeg 5.1 or later (this is 4.4); it is normalised with a plain gain capped at the true-peak ceiling, so it may read off target`, and the render does not fail. `node scripts/doctor.mjs` shows the installed version beside the 5.1 requirement as a note, never a failure.
  The `limiter reduces` figure is never negative (0 when the gain leaves the peaks under the limit). A spec with no audio ignores the flag (stderr: `loudness: this spec has no audio, so --loudness and --true-peak are ignored`), a silent mix is left as it is (stderr note), an `--out` whose temp file names (`<name>.partial.mp4`, and with a target `<name>.partial.loudnorm.mp4`) leave a name over 255 bytes exits 2 with the limit before the browser starts (a batch row: `row 0: --out: …`, exit 1, nothing rendered; `--loudness off` shortens the longer name), `--true-peak` with no target (no `--loudness`, no spec field) or with `--loudness off` exits 2, and so does a value outside the ranges, with the range in the message; neither flag goes with `--contact-sheet`.
  In a `--batch` the same applies to every row and the manifest's `sha256` is of the final normalised file. The result is byte-identical twice, with `--workers` and `--quality draft` as without; a spec with no target renders exactly as before. When the spec has `audio`, the MP4 also carries an AAC 48 kHz stereo track at 192 kb/s, mixed with normalisation off so `volume` is literal; the video length never changes because of audio. Before any frame is captured each audio file gets a decode probe on its first audio stream (a bad or video-only file fails with `audio[i].src: ffmpeg cannot decode …`, exit 1), and the whole mix graph is dry-run for 0.1 s against a generated video (an ffmpeg older than 4.4 fails with `audio: ffmpeg rejected the mix …`, exit 1).
  Every track is converted to 48 kHz stereo before mixing, so track order never changes the result. A spec without `audio` or `cues` renders exactly as before, with no audio stream. After any render that has audio, a line `audio: -17.6 LUFS integrated, true peak -3.3 dBTP` (ffmpeg `ebur128`) follows the frame count: information only, it never fails a render. `--fps` is an output override (integer 1–120); the spec's own `fps` is limited to 24/25/30/60. Two renders of the same spec and media give identical frames and audio (at any `--workers`).
  A frame is the same bytes whether it follows a walk through every earlier frame or a seek straight to its time, so a contact-sheet tile and `check.mjs` draw each element the way the MP4 does (Chromium redraws an element from a memory of how it looked, so the page renews each element whose position, scale, rotation or opacity changed in a seek, and every element under a moving camera; see `renewNodes` in `template/renderer.mjs`); the MP4 `comment` tag carries the build date, so the files differ by day unless `SOURCE_DATE_EPOCH` is set.
- `node scripts/render.mjs <spec> --batch <rows.json> --out "<dir>/<name with {index} or {var}>.mp4" [--fps n] [--size WxH] [--theme name] [--workers n|auto] [--quality draft|final] [--loudness lufs|off] [--true-peak dbtp] [--model m] [--effort e] [--agent a]` — one MP4 per row of a rows file: a JSON array of objects, each giving var values (`[{ "name": "Grace", "seats": 3 }, { "name": "Alan" }]`; a var the row leaves out takes its `default`). A key that is no declared var is an extra column: it is ignored, with a warning on stderr that names the closest var (`row 2: unknown column "cty" ignored; declared: city, name (did you mean "city"?)`), and never fails the batch.
  Every value of a declared var must be of its type, never coerced (`row 1: vars.seats: the row gives "12abc" (a string); seats is a number`), and a var with no default needs a value in every row. `--out` must hold `{index}` (the row's place, from 0) or `{<var>}` in its file name (`--batch needs an --out template with {index} or a {var}, so outputs do not collide`, exit 2), and the file name must end in `.mp4`; placeholders or any braces in the folder part as written (a folder written in `--out` must not contain `{` or `}`; the working folder may), an unknown name, or the spec's `{{name}}` form (`--out: write placeholders with single braces, like {name}`) exit 2 too, and so does a `{name}` placeholder in the file name of `--out` without `--batch` (a folder named `{draft}` is fine there).
  A value put in a file name keeps only letters, digits, `_`, `.` and `-` (each other run becomes `-`, dots and dashes at the ends go, 80 characters at most), so no row writes outside the `--out` folder; a value that leaves nothing (`""`, `/`, `..`) two rows that would write one file (compared ignoring case, `ß` as `ss`), and a file name over 255 bytes (with its temporary prefix and suffix) are errors, and so is an output that is a file the batch reads: the spec, the rows file, or any row's image, clip, sound or captions file (`row 0: --out: clip.mp4 is a file this batch reads (footage/clip.mp4); change the value or the --out template`). A number value loses its sign in a file name (`-5` gives `5`).
  Every row is substituted and checked before the first frame (the spec's own checks, `--fps` cut-offs and the output file), every row's failures printed as `row 2: scenes[0].elements[1].src: must stay inside the spec folder`, exit 1, nothing rendered; a row whose var values are wrong (a missing value, a wrong type) reports those alone, since the spec cannot be substituted without them, and its other failures show once they are fixed. Then the rows render one after another, each with its own browser and the same flags (`--workers`, `--quality`, audio, cues and captions per row): `row <i>: <out>` then the usual lines.
  Each row encodes into a hidden temp file of its own (`.<name>.<index>.partial.mp4`, which no value can produce; anything already at that name, a symlink included, is removed and the file created anew just before ffmpeg opens it by name, so a link left there beforehand is replaced, not written through, though a link planted in the instant between the two would be followed; the manifest's temp file is created exclusively, so it is never written through a link) and is renamed onto its output only when complete, so an older file under a row's name is replaced when the row succeeds and left as it was when it fails (the manifest's `status` says which: never trust a `failed` row's `out`).
  A row that fails while rendering is recorded and its temp file removed; the rest still render, and the exit is 1. After the last row every `ok` row is checked again (its file must exist and match its `sha256`), so the manifest never vouches for a file that changed.
  `manifest.json` in the `--out` folder (rewritten after every row: a temp file, then a rename; a `manifest.json` already there that is not a batch manifest, such as a web app's, is never overwritten: exit 2 before anything renders; a batch manifest is an object whose `rows` each have an integer `index` and a `status` of `ok` or `failed`) holds `{ "rows": [{ "index", "vars", "status": "ok" | "failed", "out", "sha256", "duration", "error"? }] }`: `vars` the values used (defaults filled in), `out` the file name, `sha256` of the MP4 (null when failed), `duration` the video's seconds. A rows file that is not a non-empty JSON array of objects exits 2. `--batch` with `--contact-sheet` exits 2. `--model`, `--effort` and `--agent` go into `generatedBy` after the vars are substituted, so a `{{name}}` in them is never replaced. An unknown option exits 2 and lists the accepted ones.
- ffmpeg is looked up as `$FFMPEG_PATH`, then `ffmpeg` on PATH; none is bundled or downloaded (an npm package's binary download would be unpinned and unhashed). Audio mixing needs ffmpeg ≥ 4.4 (`amix normalize`, `adelay all`); an older build fails at encode time with `Option normalize not found`.

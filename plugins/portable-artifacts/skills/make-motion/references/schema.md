# motion.json reference

Validate with `node scripts/validate.mjs motion.json`. Unknown properties are errors (with did-you-mean). All coordinates are canvas pixels (origin top-left); an element's `x`,`y` is its **centre**.

## Root
| field | type | default | notes |
|---|---|---|---|
| `format` | `16:9` \| `9:16` \| `1:1` \| `4:5` | none (the default size is `16:9`'s) | a preset: sets `size` (1920x1080, 1080x1920, 1080x1080, 1080x1350), the safe area (60 px at 1080 on the short side, every side) and the caption zone (the lower part of the safe area, from 78 % of the height down; 72 % for `9:16` and `4:5`). Use it instead of `size`; a `size` beside it must be the same one (`size: [1920,1080] does not match format "9:16" (1080x1920); drop one of them`). Video frames decode at each element's own `width` x `height`, so a preset changes nothing about them |
| `size` | `[w, h]` ints 16–3840 | `[1920, 1080]` | logical canvas, or the one the `format` sets; `render --size` rescales output |
| `fps` | 24 \| 25 \| 30 \| 60 | 30 | |
| `background` | CSS colour | the theme's page colour | |
| `theme` | shared theme name (`dusk`, `press`, `poster`, `paper`, `ink`, `blueprint`, `editorial`, `mono`, `brief`) | `dusk` | optional; see below |
| `generatedBy` | `{ model?, effort?, agent? }`, each 1–60 chars of `A-Za-z0-9 ._:/()+-` | none | provenance; shown in the preview footer and written to the MP4 `comment`/`artist` tags; missing fields read "not reported" |
| `cues` | array, up to 30 | none | procedural sound cues; see Cues below |
| `captions` | array, up to 20 | none | on-screen captions from an SRT, VTT or JSON file, in the caption zone; see Captions below |
| `texture` | `{ vignette?, grain? }` | none (off) | film texture over the whole video; see Texture below |
| `transition` | `none` \| `fade` \| `crossfade` | `none` | the default for every scene that sets no `transition`; a root `crossfade` leaves the first scene a plain start |
| `scenes` | array, 1–50 | required | total duration ≤ 120 s |

### theme
Without `theme` the spec draws as `dusk` (`render --theme` can pick another for a spec that names none). The theme's **dark** colours and fonts become the defaults: `background` is its page colour, text is its text colour, shapes without a `fill` or `stroke` use its accent, charts take its palette and axis colours, `sans` text uses its body font, `"font": "mono"` its mono font and `"role": "title"` text its display font. A weight the theme font does not ship is mapped to the nearest one it does (no synthetic bold), mono default included. Anything the spec sets itself (`background`, `color`, `fill`, a chart `config`) still wins. Fonts come from the skill's bundled `shared/fonts`, no network. An unknown name is an error with a did-you-mean.

## Scene
`id` (string, globally unique), `duration` (0.2–60 s), `elements` (array), optional `background` (a CSS colour, or `"art"`: the theme's seeded art, drawn full-bleed behind the elements in dark mode at the canvas size and seeded by the scene `id`, so the same spec always gets the same art; a light page-colour scrim dims it and text and counters on it get a soft page-colour halo), `transition` (`none` default | `fade`: scene opacity 0→1 over min(0.4 s, duration), from the page background | `crossfade`: the same fade-in, over the previous scene, which stays on screen at full opacity until the window ends (so the stage colour never shows through; the previous scene is not faded out); on the first scene it is an error, as there is nothing to fade in over). `fade` on scene 1 makes frame 0, the video's thumbnail, blank.
Scenes play sequentially; scene *n* starts at the sum of earlier durations. Only the active scene is drawn, except during the first min(0.4 s, duration) of a `crossfade` scene, when the previous one is drawn beneath it at full opacity. Timing and audio never change: a crossfade overlaps the pictures, not the clock.

## Audio
Optional root `audio` array, up to 20 tracks. Tracks mix over the whole video; contact sheets ignore them.
| field | type | default | notes |
|---|---|---|---|
| `src` | string | required | relative to the spec file; same path rules as image `src`; `mp3` \| `wav` \| `m4a` \| `aac` \| `ogg` \| `flac` |
| `at` | seconds ≥ 0 | 0 | from the video start; with `scene`, from that scene's start |
| `scene` | scene `id` | none | anchors `at` to the scene, so changing an earlier scene's duration keeps the track aligned |
| `duration` | seconds > 0 | whole clip | trim; the track stops at `start + duration`, clamped to the video end |
| `volume` | 0–1 | 1 | literal gain (the mix is not normalised) |
| `fadeIn` | seconds ≥ 0 | 0 | from the track start |
| `fadeOut` | seconds ≥ 0 | 0 | ends at the `duration` trim, else at the video end. `fadeIn + fadeOut` must fit in the time the track plays. A clip that ends earlier gets no fade (the file length is never probed). No `loop`: a short file just stops |

## Texture
Optional root `texture`: `vignette` (boolean, default off) darkens the corners with one radial-gradient layer over the scenes (clear to 55 % of the way out, 0.55 black at the corners); `grain` (0–0.15, default 0 = off) lays one static layer of monochrome film grain over each scene, as an SVG `feTurbulence` seeded from the scene `id` and never re-seeded, so the same spec renders byte-identical frames. It is blended with `overlay` and its noise averages mid-grey, so it adds texture without changing a frame's average brightness (measured: the mean luma of a frame stays within 1 of the grain-free frame at `grain` 0.15 in dusk, paper and press). A higher `grain` is stronger. Unknown keys are errors with a did-you-mean. Specs without `texture` render as before.
**Cost, measured:** the render loop (seek plus PNG screenshot, 1920x1080, 90 frames, Playwright Chromium on one Apple-silicon Mac, two rounds) took about 17 to 33 ms per frame with no texture, about 42 ms with `vignette`, about 100 ms with `grain` and about 187 ms with both. A 30 s clip at 30 fps (900 frames) therefore costs about 1 minute more with grain and about 2.5 minutes more with both. Texture applies to every scene; leave it off for long renders you do not need it on. Each scene carries its own full-frame grain bitmap (one per scene at the canvas size), so a spec with very many scenes at 4K holds a lot of memory in the page; keep `grain` for short or few-scene clips there.

## Cues
Optional root `cues` array, up to 30: short sounds the renderer synthesises, no file needed. Opt-in: a spec with no `cues` renders exactly as before, and a spec with neither `audio` nor `cues` stays silent. Cues are mixed through the same graph as `audio` tracks; contact sheets and the preview ignore them.
| field | type | default | notes |
|---|---|---|---|
| `cue` | `pop` \| `click` \| `whoosh` \| `chime` \| `impact` \| `riser` \| `swoosh` \| `typing` \| `drop` \| `ding` | required | `pop`: a 0.16 s blip with a bright tick at its start; `click`: a 0.04 s dry UI tick; `whoosh`: 0.8 s of air going past, loudest and brightest 0.4 s in (start it 0.4 s before the cut it marks); `chime`: a 1.4 s three-partial bell with a short room tail; `impact`: a 0.9 s thud whose pitch falls two octaves in its first 0.1 s; `riser`: 1.6 s of noise climbing in pitch and level, ending at full level (start it 1.6 s before the moment it builds to); `swoosh`: a 0.3 s whoosh for a transition, loudest 0.15 s in; `typing`: key clicks 0.035 s apart, one per character (0.035 s × characters + 0.05 s long); `drop`: a 0.6 s sub hit; `ding`: a 0.5 s notification ding. `whoosh`, `riser` and `swoosh` are widened above about 120 Hz (below it both channels carry the same sound, within about 1 % in level, since each channel is levelled to the same peak on its own); the rest are mono |
| `at` | seconds ≥ 0 | required (except with `follow`) | from the video start; with `scene`, from that scene's start. Must fall before the video end |
| `follow` | a `text` element `id` | none | `typing` only: the cue starts when that typing text starts typing (its scene start, or its first `value` keyframe) and clicks once per character. With `value` keyframes the clicks are spread evenly up to the first keyframe that reaches the whole text, so under an ease they only approximate the characters. Not with `at` or `scene`; counted at 0.035 s per character from where it starts typing, it must end inside the text's scene. Without `follow`, a `typing` cue is a single key click at `at` |
| `scene` | scene `id` | none | anchors `at` to the scene, as on an audio track, so changing an earlier scene's duration keeps the cue aligned |
| `volume` | 0–1 | 1 | literal gain on a cue that peaks at -6 dBFS (0.5); the mix is not normalised |
| `pan` | -1..1 | 0 | equal-power: the centre is unity in both channels, a hard pan is 3 dB louder in its channel |
| `note` | `A`-`G`, optional `#` or `b`, octave 0-8 | per cue | tunes `pop` (default E5), `chime` (A5), `impact` (F2), `drop` (C2) and `ding` (E6); an error on `click`, `whoosh`, `riser`, `swoosh` and `typing`, which are noise |
Each cue is built in layers (a short transient, a body, and on `pop`, `chime`, `impact` and `ding` a reverb tail under 0.5 s) and every cue peaks at -6 dBFS in each channel. The tones a `note` sets stay at or below 19.2 kHz (0.4 × the 48 kHz rate): the FM attack click, the pitched partials and the low-note saturation, so a high `note` never folds back into noise. To stay under it, the FM attack click of `drop`, `pop` and `ding` gets duller as the note rises (from C3, F4 and C6, so `pop`'s default E5 is already a little dulled) and stops changing from E4, A5 and E7 up; `chime` drops its third partial from G#8 and `ding` its upper partial from A8; `impact`'s glide starts no higher than 19.2 kHz from D#8; and the saturation of `impact` and `drop` is left off from G#6 and G#7. Noise is not band-limited: `click`, `typing`, `whoosh`, `swoosh`, `riser` and the attack burst of `impact` do carry some energy above 19.2 kHz. The sounds are pure functions of the cue: noise is seeded, so the same spec gives the same WAV bytes and the same MP4. A cue longer than the time left is cut at the video end, and every cue is faded out over its last 5 ms in the mix so a cut one cannot click. With `scene`, `at` must be inside that scene (a smaller `at`, or a later scene, is the fix the validator names), so a cue always starts in the scene it names; it may still ring on into the next one (a `whoosh` started 0.4 s before a cut, a `riser` building into the next scene, a `chime` tail, or the last 0.05 s of a `typing` cue).

## Elements
Common: `id` (unique across scenes and elements), `type`, `x`, `y` (required; canvas pixels, except a group's children, whose `x`, `y` are relative to the group's centre), `opacity` (0–1, default 1), `scale` (1), `rotate` (deg, 0), `keyframes`.

| type | extra fields | animatable props |
|---|---|---|
| `text` | `text` (req), `role` (`title` only; see below), `exit` (boolean, false; see below), `typing` (boolean, false; see below), `fontSize` (48), `fontWeight` 400\|500\|600\|700\|800 (600), `color` (the theme's text colour), `align` left\|center\|right (center), `maxWidth`, `font` sans\|mono | opacity x y scale rotate (+ `value` when `typing`) |
| `counter` | `to` (req), `from` (0), `decimals` (0), `prefix`, `suffix`, + text styling | + `value` (starts at `from`) |
| `shape` | `shape` rect\|ellipse\|line (req), `width`, `height`, `radius`, `fill`, `stroke`, `strokeWidth`, `elevated` (rect only), `cap` and `arrow` (line only) | + `draw` 0–1 (stroke reveal; default 1) |
| `image` | `src` (req, relative to the spec file; must stay inside the spec folder, be a regular file, no symlinks out, no dotfiles), `width`, `height` (req), `fit` contain\|cover\|fill | opacity x y scale rotate |
| `video` | `src` (req; same path rules as image; `mp4` \| `mov` \| `webm` \| `m4v`), `width`, `height` (req), `fit` contain\|cover\|fill (contain), `trimStart` (s into the clip, 0), `trimEnd` (s into the clip, the clip length), `offset` (scene s before it plays, 0), `mute` (false), `volume` 0–1 (1); see below | opacity x y scale rotate |
| `chart` | `vegaLite` (req, with inline `data.values`), `width`, `height` (req) | + `reveal` 0–1 (left-to-right wipe; default 1) |
| `group` | `children` (req, 1–40 elements; see below) | opacity x y scale rotate |
| `block` | `block` (req, a block name), `params` (req, that block's fields); see Blocks below | opacity x y scale rotate (the whole block) |

Group: `children` are ordinary elements (any type, a group too, up to 3 groups deep) whose `x` and `y` are measured from the **group's centre**, not the canvas: a group at `x: 960, y: 540` with a child at `x: 0, y: -100` puts the child at 960, 440. The group's `opacity`, `scale` and `rotate` act on all its children at once (scale and rotation turn about the group's centre), and its `x`/`y` keyframes move them together; each child keeps its own keyframes on top. A child's keyframe `t` is still seconds inside the scene. `id`s are unique across the whole spec, children included, and a validator problem in a child names its nested path (`scenes[0].elements[2].children[1].text`). `check.mjs` judges the children, not the group. A group fade is drawn as one layer, so it can differ from fading each child by one level per colour channel.

Video: real footage in a scene. The clip plays from `trimStart` to `trimEnd` starting `offset` seconds into its scene; before that it holds its first frame, and once the trimmed range ends it holds its last frame until the scene ends. It is timed by its own scene only (a scene change hides it like any element; under a `crossfade` into the next scene it stays frozen on its last frame of its own scene). Validation needs `ffprobe` (it ships with ffmpeg): it reads the clip's length, so `trimEnd` past it (`trimEnd 12 exceeds the clip length 8.5s`) and `trimStart` not before `trimEnd` (`trimStart must be less than trimEnd`) are errors; without ffprobe a spec with a video gets one error naming `doctor --fix ffmpeg`. **Render and check** decode the trimmed range once with ffmpeg (`-ss trimStart -to trimEnd`, `fps=<render fps>`, scaled to `width` x `height` by `fit`) into a frame cache, and the page shows frame `round((scene time - offset) × fps)` (held at the first and last) as an image, so every frame is exact and two renders of the same spec and clip are byte-identical. The frames are JPEG at the highest quality (PNG when the clip has an alpha channel), so the MP4 stays close to the source (measured on the 320x180 test clip in `test/video.test.mjs`: about 52 dB PSNR between the MP4 and an independent decode of the source). The cache lives in `<skill-dir>/.cache/video/<key>/` (gitignored), one folder per clip, keyed by the clip file's SHA-256, `trimStart`, `trimEnd`, the fps, the size, `fit`, alpha, the ffmpeg version and a cache format version, so a changed clip, field or ffmpeg decodes again and an unchanged one never does. A folder counts only when its `done.json` names a whole decode (a positive frame count, with the first and last frames present); anything else is decoded again. ffprobe and ffmpeg open clips and audio files through the `file` protocol only (`-protocol_whitelist file,pipe`), so a playlist renamed to `.mp4` cannot fetch anything. It grows with every new clip and size; `node scripts/doctor.mjs` lists it once it passes 2 GB, and `node scripts/doctor.mjs --fix cache` deletes it (any time; the next render decodes what it needs). The frames are decoded at the element's `width` x `height` in canvas pixels, so a `scale` keyframe above 1 or `render --size` larger than the spec's size enlarges them. **Sound:** unless `mute` is true, the clip's audio joins the mix like an `audio` track, from the moment it starts playing, at `volume`, for the trimmed length, and stops when its scene ends (the clip leaves the screen then, so its sound never plays over the next scenes); a clip without an audio stream adds nothing. **Preview** plays the clip itself in a muted `<video>` seeked to `trimStart + (scene time - offset)`: it is approximate (the nearest decodable frame, and it can lag while playing) and silent; the render is the exact one. Contact sheets and `check.mjs` use the decoded frames too, so they need ffmpeg as well.

Title role: a `text` with `"role": "title"` uses the theme's display font (the weight maps to the one the display font ships). `"font": "mono"` wins over the role: a mono title draws in the mono font, still with the entrance preset below. When it has **no** `keyframes` it gets the theme's kinetic entrance: `dusk` **rise** (fades in and rises 0.35 × `fontSize` into place, 0.9 s), `press` **ink-in** (fades in while settling from 104% scale, no movement, 1.1 s), `poster` **slam** (snaps in from 135% scale with an `outBack` landing, 0.5 s). A preset is a plain function of the scene duration and `fps`, compressed to end at least one frame before a short scene's end, so renders stay reproducible. Any `keyframes` (an empty list too) turn it off. `paper`, `ink`, `blueprint` and `editorial` have no preset.

Exit (opt-in): `"exit": true` on such a title also gives it the theme's exit, with the `exit` ease: `rise` fades as it drops 0.35 × `fontSize`, `ink-in` fades as it grows back to 104%, `slam` fades as it snaps down to 85%. The exit takes half the entrance (0.45 / 0.55 / 0.25 s) and lands one frame before the scene end, but never starts before 90% of the scene (a shorter scene gets a shorter exit, so the 85% contact frame always shows the title fully in). It is skipped on the spec's last scene, when the entrance has not landed by 90% of the scene, and whenever the title has its own `keyframes`. Without `exit` nothing changes.

Typing (opt-in): `"typing": true` on a `text` reveals its characters one at a time, 0.035 s each, from the start of its scene, with a caret after the last typed character (a thin bar; solid while typing, blinking every 0.5 s once the text is complete). Counted in grapheme clusters, so an emoji, a ZWJ sequence, a flag or a letter with a combining accent is one character and is never typed in halves. The element's box is always the full text: the untyped rest keeps its space but is not drawn, so a centred line does not shift as it fills and `check.mjs` judges its final box from the first frame. Its animatable `value` is the number of characters typed: with no `value` keyframes it runs 0 → N from t=0 at 0.035 s per character; add any `value` keyframe to take control of the start and pace (as on a counter's `value`). `typing` on any other element type is an error, and so is a `value` keyframe on a text without it. A typing text with no `value` keyframes must finish a frame before its scene ends (`0.035 × characters + 1/fps` seconds at most), or the validator says to shorten the text or lengthen the scene.

Counter default: a counter with **no** `value` keyframes counts `from` → `to` from t=0 to `min(2, 0.8 × scene duration)` seconds with `outCubic`. Add any `value` keyframe to take control of the timing.

Colours (`background`, scene `background` other than `"art"`, `color`, `fill`, `stroke`) must be hex (`#rgb`, `#rrggbb`, with optional alpha), `rgb()/rgba()/hsl()/hsla()` or a named CSS colour. `url(...)`, `var(...)` and anything else is rejected.

Theme colour tokens: a shape `fill` or `stroke` and a text or counter `color` may also name a token (`surface`, `line`, `accent`, `accentSoft`, `good`, `bad`, `warn`, `text`, `text2`, `text3`, `cat1`..`cat6`) instead of a hex. It resolves to that colour of the active theme's dark variant, so a theme change recolours the card too. Backgrounds take no tokens; an unknown name is an error that lists them. Hex specs render exactly as before.

Shape notes: a `line` has length `width`, thickness `strokeWidth` and is horizontal; angle it with `rotate`. To grow a vertical bar upward from a baseline, use a line with `"rotate": 270` and animate `draw` 0→1. `fill` defaults to the theme accent for rect/ellipse unless only a `stroke` is given. `"elevated": true` on a rect draws a card: the fill moves 6 % toward the theme text colour and a 1 px `rgba(255,255,255,.06)` highlight sits just inside the edge (no drop shadow, which would not show on a dark page); it is drawn as one extra node after the rect, is drawn in with it as `draw` grows, and is left off a rect with only a `stroke` (no fill to lift). `"elevated": false` is accepted on any shape and does nothing. `"cap": "round"` rounds a line's ends and pulls both endpoints in by half the stroke width, so the line keeps its `width`; the default stays flat. A round-cap line stays hidden until its drawn length is more than a cap radius (half the stroke width), so it grows from a stub rather than popping in as a dot. A line with an arrow needs a `width` of more than 3 × `strokeWidth` (3.5 × with a round cap) and one with a round cap alone more than `strokeWidth`; the validator names the minimum. `"arrow": "end"` adds a filled triangle head (3 × `strokeWidth` long, 3 × wide, ending at `width`) that appears once `draw` reaches 0.98.

Chart notes: data must be inline: `data.values`, or `datasets` plus `data: {name}`. Any `url` key anywhere in the Vega-Lite spec (remote `data.url`, lookup `from.data.url`, image-mark `url`) is rejected; the renderer also blocks all non-local network requests. Do not set `width`/`height` inside `vegaLite`; the element's are used. The theme's fonts, axis colours, accent and palette are applied through a built-in Vega-Lite `config`; your own `config` keys override it. The built-in config also sets: about five ticks on each axis, no y domain line, no tick marks and no vertical gridlines, bars with 10 px rounded ends and a 0.3 gap between them, lines 4 px wide with round caps and joins, and filled points ringed in the page colour (a hollow `filled: false` point keeps its accent outline). The chart `reveal` is a left-to-right wipe with a soft edge. The chart is rendered to SVG once at load.

## Blocks
A `block` element is a parameterised building block: `{ "id": "speaker", "type": "block", "x": 100, "y": 818, "block": "lower-third", "params": { "name": "Ada Lovelace", "role": "Head of Research" } }`. Before anything else reads the spec it expands into a `group` with the block's `id`, `x`, `y`, `opacity`, `scale`, `rotate` and `keyframes`, holding plain elements named `<id>/<part>` (`speaker/name`, `steps/box-2`). The parts are laid out for the canvas the spec resolves to (its `size`, else its `format`'s), sized from the short side, coloured with theme tokens only (`surface`, `line`, `accent`, `text`, `text2`, `good`), and enter with the `enter` ease over 0.6 s, 0.2 s apart; in a short scene the whole schedule is compressed so nothing moves after 85 % of the scene. Every text is at least 40 px at 1080 on the short side. The floor is relative to the short side, so it scales with the canvas: a 16:9 video shrunk to a phone's width shows that text small (about 7 px on the 360 px phone tile of a 1920-wide sheet), while at 9:16 it fills the phone. Use `format: "9:16"` for phone-first video; a text that would not fit shrinks to that floor, then wraps; sizes are estimated from the characters, since expansion runs without a page, so the room left around a text is generous. A block goes directly in a scene's `elements`, not inside a group. `node scripts/blocks.mjs list` prints every block's params, and `node scripts/blocks.mjs show <name>` prints one block's params table, its place on each format and an example element. `references/blocks/<name>.png` is the contact sheet of `references/examples/blocks/<name>.json`, for human review (CI never compares it: fonts rasterise differently per OS).

| block | params (`?` optional; strings up to 80 characters unless noted) | what it draws; `x`, `y` |
|---|---|---|
| `title-card` | `title`, `subtitle?`, `kicker?` | an accent kicker, the title in the display font (shrinks to fit three lines), an accent rule, the subtitle; centred on `x`, `y` (the canvas centre) |
| `lower-third` | `name`, `role?`, `side?` (`left` \| `right`, default `left`) | the name and role on a card with an accent bar on its outer edge; `x`, `y` is the **bottom corner of that outer edge** (bottom-left for `left`, bottom-right for `right`), and the card grows up and inward, so its bottom stays at `y` whatever the text. Its place: the outer edge 40 px inside the safe area, the bottom 24 px above the caption zone: `x 100, y 818` at 16:9 (`x 1820` for `right`), `x 100, y 1358` at 9:16 (`x 980` for `right`); there the card never reaches the caption zone, even with 80-character name and role |
| `kpi-counter` | `label`, `to`, `from?` (0), `prefix?`, `suffix?` (each up to 6), `decimals?` (0–4), `delta?`; `to` and `from` at most 999999999999 either side of 0, so the widest number fits one line at 40 px on 9:16 | a card with the label, the number counting `from` → `to` over 2 s once it is in (sized to fit on one line), and the delta, in `good` when it starts with `+` or `↑`, else in `text2` |
| `step-flow` | `steps` (2–6, each up to 24), `direction?` (`row` \| `column`) | numbered boxes joined by arrows, box then arrow in turn. Default `row` on a wide canvas, `column` on a tall one; a row whose boxes are too narrow for a label word at 40 px is laid out as a column. A column takes the largest label size and roomiest spacing that fit the band from the safe area top to the caption zone (to the safe area bottom without captions); its place centres it in that band: `x 960, y 451` at 16:9, `x 540, y 721` at 9:16 |
| `quote-card` | `quote` (up to 200), `attribution?` | a card with an accent quotation mark, the quote (shrinks to fit five lines, never below 40 px) and `— attribution` (no dash is added when it starts with one). The quote, mark and padding shrink until the card fits the band from the safe area top to the caption zone when the spec has captions (else to the safe area bottom); its place centres it in that band, `x 960, y 451` at 16:9, `x 540, y 721` at 9:16, so a 200-character quote with captions stays above them on every format |
| `checklist` | `items` (2–8, each up to 40), `tickAfter?` (0.1–2 s, default 0.25) | one row per item with an empty circle; once every row is in, each item is ticked in turn (a `good` circle and a tick drawn in), `tickAfter` seconds apart. Every row uses one font size, the largest (48 down to 40 px) at which the rows, with the roomiest spacing that works, fit the band from the safe area top to the caption zone when the spec has captions, else to the safe area bottom. Its place centres it in that band: `x 960, y 451` at 16:9, `x 540, y 721` at 9:16. On 1:1, eight items of about 40 characters wrap to two lines and do not fit at 40 px; `check.mjs` then names `params.items`: use fewer or shorter items |
| `logo-outro` | `src` (a file next to the spec, as an image `src`), `tagline?`, `width?` (40–1600 px, default 480) | the logo fitted into a `width` × `width / 2` box, settling in from 92 %, then the tagline |
| `cta-close` | `headline`, `action` (up to 24), `url?` | the headline in the display font, an `accent` button with the action, and the address as monospace text (nothing is linked or fetched) |

`x`, `y` is the block's centre except for `lower-third`; `checklist`, `step-flow` and `quote-card` place it higher than the canvas centre (see above). Blocks never add sound: put cues in `cues` yourself (a `pop` as a part lands, a `ding` when a count ends). The parts enter from opacity 0, so a block alone in the first scene leaves frame 0 blank and `check.mjs` warns about the thumbnail; put a visible element or `"background": "art"` beside it when the first frame matters. Validation checks a block as written, before it expands: an unknown name (`scenes[0].elements[0].block: unknown block "kpi"; did you mean "kpi-counter"? (blocks: title-card, …)`), the block's params against its schema (`scenes[0].elements[0].params.title: must NOT have more than 80 characters`, `params.side: must be one of "left", "right"`, `params.items: must NOT have fewer than 2 items`), the file a `logo-outro` names (`params.src: file not found: logo.png`), the block's own fields and keyframes, and a block inside a group. Params that pass always expand into a valid spec; the expanded spec then goes through every check above, and anything that still lands inside a block (an `id` another element also uses, such as `kpi/label`) is reported at the block; a block `id` used twice is one error at the second block's `id`. `check.mjs` reports a finding about a part at the block too, naming the block, the part and what to change, matched to the finding: outside the safe area `scenes[0].elements[0]: text "lt/name" leaves the safe area (right) at 0.90s (block "lower-third", part "name"); shorten params.name or move the block`; in the caption zone the finding already says to move it above the zone, so only the block and part are added; overlapping another block's text `…; move one of the blocks or shorten params.name` (another element's: `move the block or the other element`).

## Keyframes
`{ "t": seconds, "ease": name, <prop>: value, ... }`
- `t` is relative to the scene start, sorted ascending, ≤ scene duration.
- Per property the track is built from the keyframes that set it: before the first, the value is that keyframe's value; between two, it interpolates using the **destination** keyframe's `ease` (default `linear`); after the last, it holds. Properties no keyframe sets keep the element's base value.
- Sampling: frame *i* shows time *i / fps*, so the last frame is one frame **before** the scene/video end. Put the final keyframe at least one frame (1/fps s) before the scene end, or it is never shown fully.
- `ease`: `linear`, or `in|out|inOut` × `Quad|Cubic|Quart|Back|Elastic|Bounce|Sine|Expo|Circ`, or a named ease: `enter` (cubic-bezier 0.16, 1, 0.3, 1: fast out, soft settle, for entrances), `exit` (0.6, 0, 0.9, 0.35: slow start, accelerating away), `move` (0.65, 0, 0.35, 1: symmetric, for a move between two places), `land` (0.55, 0, 0.2, 1.12: overshoots about 1% just before it lands; one hero moment per clip; never on a counter's `value`, where the number would show past its target). See `motion-design.md`.

## Captions
Optional root `captions` array, up to 20 tracks: the words of a captions file on screen, one group at a time, centred in the caption zone (see `format`; the lower part of the safe area). Opt-in: a spec with no `captions` renders exactly as before.
| field | type | default | notes |
|---|---|---|---|
| `src` | string | required | relative to the spec file; same path rules as image `src`; `srt`, `vtt` or `json`. A JSON file is Whisper output (`segments[].words[]` or a top-level `words` array, each `{ word` or `text`, `start, end }` in seconds; segments without `words` are timed like cues) or the voice sidecar `voice.mjs` writes (`{ sentences: [{ text, start, end }] }`) |
| `style` | `plain` \| `pill` \| `karaoke` \| `kinetic` \| `boxed` \| `typewriter` | `plain` | `plain`: the text with a soft page-colour shadow; `pill`: on a rounded backdrop of the theme `surface` at 0.85 alpha; `karaoke`: the word being spoken in the theme accent; `kinetic`: the word being spoken in the theme accent colour, popping from 1.15x to its size over its first 0.15 s (less when a bigger pop would take the word out of the caption zone: a word as wide as the zone does not pop); `boxed`: on a square-cornered `surface` backdrop at 0.85 alpha; `typewriter`: each group types in, one character every 0.035 s |
| `at` | seconds ≥ 0 | 0 | where the file's time 0 falls: from the video start; with `scene`, from that scene's start. Only one track may be on screen at a time: two tracks whose groups overlap before the video ends are an error (`captions[1]: on screen at 1.50s together with captions[0]; …`) |
| `scene` | scene `id` | none | anchors `at` to the scene, as on an audio track; give a voiceover's captions the same `scene` and `at` as its audio track so they stay together |

**Timing.** An SRT or VTT cue is split into words at spaces; each word gets a share of the cue's time in proportion to its characters plus one for the space after it (none for the last word), and the last word ends at the cue's end. A voice sidecar sentence and a Whisper segment without words are timed the same way; Whisper words are used as given. A cue must start after the one before it (`cue 3 (line 9): start 00:00:01,000 is not after the previous cue's start 00:00:02,000; sort the cues by time`), and a cue that runs past the next one's start is cut there. A cue with no words is skipped. Only tag-shaped markup is dropped (`<i>`, `<b>`, `<u>`, `<font …>`, `<c.class>`, `<v Name>`, `<lang …>`, `<ruby>`, `<rt>`, karaoke timestamps such as `<00:00:01.000>`, and `{\an8}` overrides) and `<br>` / `<br/>` becomes a space, so `a<b and c>d` stays as written; `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`, `&nbsp;`, `&#NNN;` and `&#xHH;` are decoded. In an SRT file a second timing line inside a block starts a new cue (the blank line before it was missing; a cue number just above it goes with it). A UTF-8 byte-order mark is ignored in every format. With the voice sidecar the sentence edges are exact but word times inside a sentence are these estimates, so `karaoke` and `kinetic` from a sidecar are approximate; Whisper word timings are exact, and aligning a synthesised voiceover word by word is not built in.

**Grouping** (HyperFrames' caption rules). One group is on screen at a time, 2 to 6 words and at most 42 characters (an emoji or a CJK character counts as one; a word is never split, so one longer word is a group of its own). A new group starts after a word that ends a sentence (ending in `.`, `!`, `?`, `。`, `！`, `？`, `…` or `‽`, also before closing quotes or brackets, as in `"go."` or `(done!)`), after a pause of 0.15 s or more, at 6 words, or before a word that would take the group past 42 characters. A one-word group then joins the next group when it is at most 0.5 s away and the result keeps to 6 words and 42 characters, else the previous group under the same conditions, else it takes the adjacent word of a neighbour that can spare one, never a word that ends a sentence (so `one two three four five six seven` shows as five words, then two); a word with no group within 0.5 s, or a one-word track, stays alone. Each group ends when the next starts, or at its last word's end. Nothing shows before 0.1 s: groups that end by then are dropped and the first one left starts at 0.1 s at the earliest; a track that would show nothing at all is an error (`nothing would show: every word ends by 0.1 s into the video; …`).

**Look.** One layer per track, over the scenes and under `texture`, so it does not fade or crossfade with a scene. The text is the theme's body font at its shipped weight nearest 700, 48 px at 1080 on the short side (48 px at 1920x1080 and 1080x1920), in the theme's text colour. The layer is at most the zone's width; a long group wraps onto balanced lines (a 42-character group takes at most two), a word too long for a line breaks anywhere, and a group taller than the zone is shrunk to fit it. A number with its unit stays on one line, as in a text element. `check.mjs` fails on a visible text or counter held in the caption zone while a caption is on screen, and on a captions layer outside the zone (see CLI).

## Cross-field errors (examples)
- `scenes[1].elements[0].id: duplicate id "title" (first used at scenes[0].elements[0].id)`
- `scenes[0].elements[0].keyframes[1].draw: not animatable on text; animatable: opacity, x, y, scale, rotate`
- `scenes[0].elements[0].keyframes[2].t: 5 exceeds scene duration 3`
- `scenes[0].elements[0].keyframes[0].value: not animatable on text; animatable: opacity, x, y, scale, rotate (value needs "typing": true)`
- `texture.grain: must be <= 0.15`
- `scenes[0].elements[0].text: typing 100 characters takes 3.50s but scene "one" lasts 1s (it must finish a frame before the scene ends at 30 fps); shorten the text or lengthen the scene to at least 3.54s` (render.mjs asks again with its `--fps`, which replaces the spec's)
- `scenes: total duration 121s exceeds the 120s limit`
- `audio[0].src: unsupported audio format ".wma"; use mp3, wav, m4a, aac, ogg or flac`
- `audio[1].scene: scene "outro" not found; scenes: intro, chart`
- `audio[1].at: starts at 9s (scene "chart" + 4s), but the video ends at 8s`
- `cues[1].cue: must be one of "pop", "click", "whoosh", "chime", "impact", "riser", "swoosh", "typing", "drop", "ding"; did you mean "chime"?`
- `cues[0].at: 2s is past the end of scene "two", which lasts 2s; use a smaller at, or put the cue in a later scene`
- `cues[0].note: click has no pitch; note is for pop, chime, impact, drop and ding`
- `cues[0].follow: element "title" is not a typing text (set "typing": true on it, or drop follow)` (also `only typing takes follow`, and `cues[0].at: not with follow; the cue starts when "title" starts typing`)
- `cues[0].follow: "title" types past the end of scene "one"`
- `captions[0].src: cue 3 (line 9): end 00:00:04,000 is before start` (also `unsupported captions format ".txt"; use srt, vtt or json`, `no captions found; expected SRT or WebVTT cues …`, `cue 2 (line 5): no timing line such as "00:00:01,000 --> 00:00:02,500"`, `cue 1 (line 1): end 00:00:01,000 is not after start 00:00:01,000; make the cue last at least 1 ms`, `nothing would show: every word ends by 0.1 s into the video; start the track later with at, or fix the times in the file`, and for JSON `words[3]: end 1.2 is before start 1.5` or `words[0]: no "word" or "text"; give every word its text`)
- `captions[1]: on screen at 1.50s together with captions[0]; only one captions track can show at a time: move one with at or scene, or merge the files`
- `audio[0].fadeOut: fadeIn 1s + fadeOut 2.5s exceed the 3s the track plays (from 2s to the video end at 5s)`
- `scenes[0].elements[1].src: file not found: pic.png` (also `must stay inside the spec folder`, `hidden files are not allowed`)
- `scenes[0].elements[2].trimEnd: trimEnd 12 exceeds the clip length 8.5s` (also `trimStart: trimStart must be less than trimEnd`, `src: unsupported video format ".gif"; use mp4, mov, webm or m4v`, `src: ffprobe not found (needed to check video elements); install ffmpeg: node …/doctor.mjs --fix ffmpeg`)
- `scenes[0].elements[0].fill: must be a CSS colour (hex, rgb(), rgba(), hsl(), hsla() or a named colour) or a theme token: surface, line, accent, ...`
- `scenes[0].transition: crossfade needs a previous scene to fade in over; use "fade" or "none" on the first scene`
- `scenes[0].elements[1].cap: only valid on a line shape` (also `elevated: only valid on a rect shape`, `arrow: only valid on a line shape`)
- `scenes[0].elements[0].vegaLite.layer[1].data.url: remote data is not allowed — inline data.values`
- `background: must be a CSS colour (hex, rgb(), rgba(), hsl(), hsla() or a named colour)` (for `"art"` on the root: `; "art" is only valid as a scene background`)
- `scenes[0].elements[0].role: unknown role "heading"; did you mean "title"?`
- `scenes[0].elements[0].vegaLite.data.values: required — chart needs inline data.values`

## CLI
- `node scripts/validate.mjs <spec> [--json]` — exit 0 / 1 / 2.
- `node scripts/blocks.mjs list` / `node scripts/blocks.mjs show <name>` — the blocks and their params (see Blocks). Exit 0, or 2 for an unknown command or block (`unknown block "kpi"; did you mean "kpi-counter"? (blocks: …)`).
- `node scripts/voice.mjs "<text>" | --text-file <file> --out <file.wav> [--voice af_heart] [--speed 0.5–2]` / `--list-voices` — synthesises a voiceover locally with Kokoro (kokoro-js, Apache-2.0; 24 kHz mono wav; prints the wav path, the duration and the sidecar path; also writes `<file>.json` beside the wav with `{ sampleRate, voice, sentences: [{ text, start, end }] }`, times in seconds from the clip start). Needs `cd <skill-dir> && npm install kokoro-js@1.2.1 --no-save` (on demand, not part of `npm ci`) and a one-time ~90 MB model download into `<skill-dir>/.cache/models`; offline after that. Exit 0 / 2 usage or not installed / 1 synthesis error.
- `node scripts/preview.mjs <spec> [--open]`
- `node scripts/check.mjs <spec> [--json] [--theme name]` — seeks the render page to every contact-sheet moment (all of them, uncapped); flags a visible text or counter outside the safe area (60 px at 1080 on the short side, on every side: 60 px at 1920x1080, 120 px at 3840x2160) while it is not moving (between or after its keyframe tweens), two visible texts or counters overlapping while neither is moving or fading, and a scene that ends with nothing on screen (every element invisible or wholly off the canvas; a title whose `exit` preset was applied counts as present, since it left on purpose). With `captions`, also a visible text or counter whose box reaches into the caption zone while it is not moving and a caption is on screen (`scenes[0].elements[1]: text "sub" sits in the caption zone (y >= 842) at 1.00s; move it above y 842 or end the captions before it`; with no caption showing, the lower band is free; judged at the sheet moments and at every caption group's midpoint), and a captions layer that leaves the zone (`captions[0]: captions leave the caption zone (right) at 1.40s`, video time). Each layer is measured once per caption group, at its midpoint (and for `kinetic` at each word's start, where the pop is largest), as the box around the layer and every word, so transforms and the pop count. A **warning**, never a failure (exit stays 0; printed to stderr as `warning: scenes[0]: ...`, and under `warnings` in `--json`, which is left out when there is none), when the first scene shows nothing at t = 0, since that blank frame is the video's thumbnail; the message names the cause (a `fade`, an opacity 0 first keyframe such as a title's theme entrance, a line or chart at `draw`/`reveal` 0, or a typing text with no characters typed yet: its caret alone is not content). An `art` background counts as shown. A crossfade window is sampled at its midpoint, and a visible text or counter of the incoming scene that overlaps one of the outgoing scene there is a warning too (`warning: scenes[1].elements[0]: text "b" overlaps text "a" of the outgoing scene ...`). A box wholly off the canvas has left the frame and is never clipped. `--theme` is the theme for a spec that sets none, as in render.mjs (an unknown name exits 2). A crash prints `check crashed: …` alone (JSON `crashed: true`). Exit 0 ok (or `check: skipped (no browser: …)`), 1 problems, 2 usage.
- `node scripts/render.mjs <spec> [--out file.mp4] [--fps n] [--size WxH] [--theme name] [--model m] [--effort e] [--agent a] [--contact-sheet]` — `--model`/`--effort`/`--agent` override the spec's `generatedBy` (hostile values fail validation, exit 1); `--theme` is a shared theme for a spec that sets none (a spec's own `theme` wins; an unknown name exits 2). Default out `<specdir>/out/<name>.mp4`; with `--contact-sheet`, `--out` is a directory and PNGs go to `<out>/contact/<scene-id>.png` (default `<specdir>/out`). `--size` sides must be 16–3840 and even. Output is written to `<name>.partial.mp4` and renamed on success; Ctrl+C removes it (exit 130/143). When the spec has `audio`, the MP4 also carries an AAC 48 kHz stereo track at 192 kb/s, mixed with normalisation off so `volume` is literal; the video length never changes because of audio. Before any frame is captured each audio file gets a decode probe on its first audio stream (a bad or video-only file fails with `audio[i].src: ffmpeg cannot decode …`, exit 1), and the whole mix graph is dry-run for 0.1 s against a generated video (an ffmpeg older than 4.4 fails with `audio: ffmpeg rejected the mix …`, exit 1). Every track is converted to 48 kHz stereo before mixing, so track order never changes the result. A spec without `audio` or `cues` renders exactly as before, with no audio stream. After any render that has audio, a line `audio: -17.6 LUFS integrated, true peak -3.3 dBTP` (ffmpeg `ebur128`) follows the frame count: information only, it never fails a render. `--fps` is an output override (integer 1–120); the spec's own `fps` is limited to 24/25/30/60. Two renders of the same spec and media give identical frames and audio; the MP4 `comment` tag carries the build date, so the files differ by day unless `SOURCE_DATE_EPOCH` is set.
- ffmpeg is looked up as `$FFMPEG_PATH`, then `ffmpeg` on PATH, then an optionally installed `ffmpeg-static`. Audio mixing needs ffmpeg ≥ 4.4 (`amix normalize`, `adelay all`); an older build fails at encode time with `Option normalize not found`.

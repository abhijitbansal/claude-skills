The verdict

An outline, not a page, keeps explainers consistent

Good

You write the facts; the tool owns the layout. The page is always well formed, offline and the same family as every other one.

  • The model fills typed sections in JSON and never writes HTML, CSS or script.
  • Checks run before the build: schema, file references, prose rules.
  • One theme, one accent and one set of components keep every page consistent.

The problem

A hand-written page drifts, a generated one cannot#

A page written freehand looks fine once. The second one uses a different spacing scale, the third a different set of colours, and the fourth quietly pulls a font from a CDN.

With an outline, the layout is not up for discussion. Each section type has one renderer, and the renderer is the only place that knows about markup. The title of a section is a claim a reader can agree or disagree with, not a label such as "Overview".

Text fields accept a small subset of markdown: bold, italic, code, links to https pages and - lists. Anything else is shown as plain text, so a stray angle bracket can never become a tag.

Guarantees

Four rules keep the output trustworthy#

  • Closed vocabulary

    schema

    Tones, severities and changes come from fixed lists. A typo gets a did-you-mean hint instead of a silent default.

  • Files stay local

    paths

    Images and diagrams resolve inside the spec folder. Absolute paths, parent folders and symlinks are refused.

  • Plain prose

    lint

    A lint rejects filler phrases and placeholder text before the page exists.

  • Status needs a word

    a11y

    Severity, change type and step status each show a shape and a label, never colour alone.

Trade-offs

Typed sections trade freedom for consistency#

Freehand HTML

Caution
  • Any layout you can imagine
  • Every page needs a design pass
  • Easy to ship a broken or networked page

Typed outline

Good
  • Nineteen section types, all themed
  • Checked before it is built
  • Cannot load anything from the network

Verdict. Use the outline for recaps, checklists and concept pages. Reach for a bespoke page only when the layout itself is the point.

History

The design settled in three passes#

  1. Pass 1 Schema first

    Closed section types, limits and did-you-mean errors.

  2. Pass 2 Renderers

    One module per type, each with an escaping test.

  3. Pass 3 Runtime

    Theme toggle, contents highlight and copy buttons.

WarningText is escaped, not trusted

A field such as <img onerror=alert(1)> is shown as characters on the page. If you need real markup, the section type is missing, not the escape.

Why not let the model write HTML directly?

It can, but then every page needs its own review for network calls, broken markup and style drift.

  • The outline removes that review.
  • It also makes pages diffable: a change is a change to JSON.

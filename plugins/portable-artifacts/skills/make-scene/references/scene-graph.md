## Shared contract: scene graph v1

Every world/lift module returns this object; the browser runtime consumes exactly this. Colour values are a **ColourRef**: a theme token name (`cat1`…`cat8`, `page`, `surface`, `text`, `text2`, `line`, `grid`, `accent`, `good`, `warn`, `bad`, `glow`), a `#rrggbb` hex, or `{ "base": "#rrggbb", "tint": <token>, "share": 0..1 }` (mixed at runtime, so it follows the theme toggle). In the mix, `share` is the fraction of the theme `tint` mixed INTO the fixed `base`: `0` is exactly `base`, `1` is exactly the tint, per 8-bit channel. A world keeps its identity this way: the forest meadow is a green `base` with 30% of the page surface, and group steps are the category colour at 60% over white (lighter) or black (darker).

```json
{
  "v": 1,
  "kind": "city|forest|galaxy|terrain|diagram|chart",
  "title": "…",
  "units": "commits",
  "bounds": { "min": [0,0,0], "max": [0,0,0] },
  "camera": { "position": [0,0,0], "target": [0,0,0] },
  "env": { "sky": "theme|space", "ground": null, "fog": true, "stars": false, "water": null, "nightLights": true },
  "groups": [ { "name": "api", "colour": "cat1" } ],
  "items":  [ { "id": "i0", "label": "api · W30", "group": 0, "t": "2026-W30", "value": 12, "display": "12 commits" } ],
  "batches": [ { "id": "b0", "shape": "box|cylinder|sphere|icosa|cone|disc|ring", "colour": "<ColourRef>", "emissive": null, "flat": false,
                 "instances": [ [0,0,0, 1,1,1, 0] ] } ],
  "tubes":   [ { "id": "e0", "points": [[0,0,0],[1,0,0]], "radius": 0.06, "colour": "<ColourRef>", "item": null, "label": "api → web", "display": "6 commits", "arrow": "end" } ],
  "surfaces":[ { "id": "s0", "nx": 2, "nz": 2, "size": [10,6,4], "heights": [0,0,0,0], "bands": [ { "below": 0.9, "colour": "#d8c38a" } ], "cells": [0] } ],
  "labels":  [ { "text": "api", "at": [0,0,0], "size": 0.6 } ],
  "anim":    { "sway": ["b1"], "orbits": [ { "batch": "b2", "center": [0,0,0], "r": [1.4], "phase": [0.3], "speed": [0.7] } ] },
  "focus":   { "api": { "position": [0,0,0], "target": [0,0,0] } },
  "tour":    [ { "title": "…", "caption": "…", "focus": "api", "path": null, "reverse": false } ],
  "fallback": { "kind": "table|svg", "columns": ["group","t","value"], "rows": [["api","2026-W30","12"]], "svg": null,
                "links": { "columns": ["from","to","value"], "rows": [["api","web","6 commits"]] } }
}
```

- Each instance is `[x, y, z, sx, sy, sz, itemIndex]`. `itemIndex` is −1 for decoration such as trunks and branches.
- `ring` is a flat annulus in the xz plane (outer diameter 1, a hairline wide), so `[cx, cy, cz, 2r, t, 2r, -1]` is a circle of radius `r`. The runtime draws it translucent and unlit and never hovers it: it is scenery that neither hides nor shows data.
- `surfaces[].cells` maps each data cell to an item index.
- `focus` keys are lowercased group names, row labels, or node ids (a diagram lift adds edge and message ids: a view of the whole route).
- Numbers are rounded to 3 decimals, so the goldens are stable.

## Conventions the worlds follow

These pin down what the contract leaves open. The runtime must read them the same way.

- **Instances.** A unit shape (box 1x1x1, cylinder diameter 1 and height 1, sphere diameter 1, cone, disc, icosahedron, ring) is scaled by `[sx, sy, sz]` and centred on `[x, y, z]`. There is no rotation. A building of height `h` on the ground is `[x, h/2, z, w, h, w, i]`.
- **Items.** `items[i]` is input row `i`. `t`, when present, is a string. `label` is the row's `label`, else `"<group> · <t>"`, else the group. `items[].value` is the exact input value (the one number that is not rounded to 3 decimals) and `display` shows it in full with en-US digit grouping.
- **`batches[].emissive`** is `null` or `{ "colour": <ColourRef>, "density": 0..1 }`: the share of lit windows. City buckets buildings into four density levels by `value / max`, so one batch holds one level of one group.
- **`env.ground`** is `null` or a ColourRef for a ground disc sized from `bounds` (its radius is 1.5 half-diagonals plus 2). The disc is solid under the scene and fades to nothing between half its radius and its rim, so no edge is ever framed.
- **`env.water`** is `null` or `{ "y": <normalized height 0..1> }`. The runtime scales it by `surfaces[0].size[2]`. The sea is a solid disc 1.7 half-diagonals of the surface wide, fading at its rim like the ground, so the seabed under the margin of the surface never shows.
- **Surfaces.** `size` is `[sx, sz, sy]`: the world width (x), depth (z) and the height that `heights == 1` maps to. The mesh is centred on x and z, sits on y = 0, and `heights` is row-major (`heights[iz * nx + ix]`) in 0..1. Band `below` values are in the same 0..1 units; a height at or above the last `below` takes the last band.
- **Terrain cells.** The data grid sits inside a ring of empty cells, so the land slopes down to the sea on every side and reads as an island. With `T` columns (by sorted `t`, along x) and `G` rows (by group, along z), the padded grid has `T + 2` columns and `G + 2` rows; data column `ti` and data row `gi` is cell `(gi + 1) * (T + 2) + ti + 1`, on vertex `(ix, iz) = ((ti + 1) * 5, (gi + 1) * 5)` of the 5x-upsampled grid, so `nx = (T + 1) * 5 + 1` and `nz = (G + 1) * 5 + 1` (a grid of one column or one row is no special case). A cell with no row, and every cell of the ring, has item index `-1` and value 0; so every vertex on the outer edge of the surface is at height 0. Between cells the heights follow a monotone cubic (PCHIP, separable), which is exact at every data cell (so a data vertex is always `value / max`) and never rises above the higher of the two cells it runs between. The surface is `T + 1` cell pitches wide and `G + 1` deep (a pitch is at most 2.5), the data one pitch in from each edge. A heatmap surface (a dashboard lift) keeps the older convention: no ring, a data cell on every 5th vertex from 0, a one-column or one-row grid padded to two vertices.
- **City layout.** Districts (groups) are rows along z in order of first appearance. Within a row, buildings go along x by `t` (numbers numerically, then strings, no locale), with one shared column per distinct `t`. Duplicate `(group, t)` rows take neighbouring slots and are never summed. Rows with no `t` follow, tallest first. Height is `0.15 + value / max * 9`; value 0 draws a flat 0.05 marker.
- **Group colours.** Groups 0–7 are `cat1`…`cat8`. Groups 8–15 are `{ base: "#ffffff", tint: catN, share: 0.6 }` (lighter step) and 16–23 are `{ base: "#000000", tint: catN, share: 0.6 }` (darker step), so all 24 are distinct.
- **Focus.** One entry per group name and per non-empty row label, keys lowercased (own keys, so a group named `constructor` or `__proto__` still has one); a group wins over a label of the same name. A diagram lift also has one entry per edge or message id (a view of the whole route, so a hop's light is in shot end to end).
- **Tubes and links.** A galaxy link is one tube. `tubes[].label` (optional) is `"<from> → <to>"`; `tubes[].display` (optional) is the link's exact value through the same formatter as `items[].display` (digit grouping, then units), and is omitted when the link has no value. `fallback.links` (optional, galaxy only, present when there is at least one drawn link) is a second table `{ columns: ["from","to","value"], rows: [[from, to, valueText]] }` of 3 strings per row; `valueText` is `""` without a value. Links are between two different groups; the validator rejects `from === to`, and the galaxy skips one defensively. `assertGraph` checks these fields. `tubes[].arrow` (optional) is `"end"` or `"both"`: a cone at the last point of the route (and the first, for `both`), tip on the end point, pointing away from the neighbouring point; absent means no head. Galaxy links have none.
- **Orbits.** `anim.orbits[k]` animates the instances of batch `batch`, one entry per planet batch; `center`, `r[]`, `phase[]` and `speed[]` run parallel to that batch's `instances`. At time `T` seconds the angle is `φ = phase + speed * T` (radians; `speed` is radians per second, `0.9 / sqrt(r)`), and the position is `x = cx + r·cos φ`, `z = cz + r·sin φ`, `y` unchanged. With +y up, increasing φ turns clockwise seen from +y (counter-clockwise seen from below). The stored instance `[x, y, z, …]` is already the time-0 position (`T = 0`), so a static render needs no animation. `r` is `1.4 + rank * pitch` with `pitch = min(0.32, 6.6 / max(1, n − 1))` for `n` planets in the system, so no orbit exceeds r = 8. Phases are seeded from `seedFrom("<group>|<row index>")`, never random. The galaxy also lists one `ring` instance per planet (`[cx, cy, cz, 2r, 0.02, 2r, -1]`) in a last batch of its own, so each orbit shows as a faint circle; the planet batches keep their ids.
- **Bounds.** `bounds` also covers each orbit disc: `center ± max(r)` in x and z.
- **Sway.** `anim.sway` lists the id of every leaf batch (one entry per `icosa` batch), and only those; trunk and branch batches stay still.
- **Emissive density.** For city windows, `density` is the share of lit windows (0..1). For a galaxy star it is `1`: the whole sphere is self-lit, and the runtime must not treat it as a window mask.
- **Tour.** Worlds return `tour: []`. The build step fills it from the spec's beats: `focus` is the first of the beat's focus entries (lowercased) that is a key of `graph.focus`, else its first entry; `caption` is `""` when the beat has none; `path` is `null` and `reverse` is `false`. A beat whose focus is not a key shows its caption and leaves the camera where it is. A diagram hop's `focus` is the edge's own id (its view frames the whole edge, so the light is in shot from end to end), the node it ends at only when the edge has no view of its own. A diagram lift with no spec `tour` builds its own beats from the diagram's `stories` (at most 12), with `path` set to the id of the tube to ride and `reverse` true when the beat plays against the edge's direction (a reply).
- **Labels.** `labels[]` is drawn by the page as HTML text over the canvas, never as 3D geometry: each label is projected from `at` after every frame, sized from `size` and its depth (clamped to a readable range), and hidden when it is behind the camera or off the frame, or when it overlaps a nearer label (a screen-space pass after every frame: nearer wins, a hidden label never hides another). A label is at most 40vw wide (and 90% of its host); a longer one is cut with an ellipsis (the full text is not otherwise shown: Explore lists group and item names only, not every label such as axis ticks or diagram group labels). They are not occluded by the scene. The PNG export paints them onto the saved image, cut the same way.
- **Framing.** The runtime frames the scene on open: it keeps the side of `camera.target` the graph camera is on (lifted to at least 24° above the floor), and puts the camera exactly as far back as the scene's own points need (instance corners, ring circles, tube points, label anchors, surface corners) for the viewport's aspect, in or out, with 20% to spare. `camera.position` is therefore only a direction. Fog starts and ends at 1.4 and 4.5 fitted distances. The orbit never goes flatter than 20° above the floor. A focus view is authored for a square viewport: in a narrower one its distance grows by 1/aspect, never past the fitted overview distance.
- **Test hook.** Test-only: enabled by `?test=1` in the page URL, it exposes `window.PAScene.__project(itemIndex)` (the viewport point on an item) and `window.PAScene.__scene` (the first scene's api).
- **Tooltip.** An item shows `label` and `display`. A tube with `label` or `display` shows those (a link's value is readable exactly); a tube is hoverable when it has either or an `item`.
- **Fallback.** `fallback.rows` is a table of strings (`columns` names them) and `fallback.links` a second one. A lift adds `fallback.svg` (its 2D drawing), optionally `fallback.svgDark` (the dark-theme drawing: both ship and the page theme chooses, as in make-explainer's charts) and `fallback.css` (styles for that svg, included once on the page). The data block that carries the graph in the page leaves `fallback` out: the runtime never reads it.
- **Travelling light.** When a tour beat has a `path`, the runtime flies the camera to the beat's `focus` and sends a glowing sphere (the `glow` colour, a halo around it) along the tube with that `id`: from its first point to its last, or last to first when `reverse`, over 1.8 seconds, eased. It stays at the end until the next beat; a beat with no `path`, or closing the tour, hides it. Under reduced motion the sphere appears at the far end at once (the start when `reverse`). The sphere follows the same curve the tube is drawn along and is never hoverable.
- **Diagram lift.** `kind` is `"diagram"`, 2D px / 40 is world units. Graph layouts (architecture, flow, state) lie on the floor: ELK x is world x, ELK y is world z, nodes are blocks (`database`/`storage` cylinder, `queue` three stacked boxes, `start`/`end` disc, `decision`/`choice` cone, else box), groups are `line` platforms 0.1 thick whose top is `0.1 * depth` (a nested group stands on its parent), and edges are tubes at y 0.3 along ELK's points with rounded corners (solid `text`, `dashed` `text2`, `async` `accent`), each ending in an arrowhead (`tubes[].arrow` is `"end"`, or `"both"` for a two-headed edge; a message in a sequence diagram points at its receiver). The runtime draws the head as a cone at the end of the route, pointing along its last segment, sharing the tube's colour. A group label stands at its platform's back-left corner, so a nested group never shares its parent's anchor. A sequence diagram stands up: participants are pillars at their lifeline x, and message `i` is a tube at `y = top - i * 0.9` (the first message is the highest). `graph.groups` are the node kinds (the legend), `items` are the nodes or participants (`value` 0; `display` is the node's `detail`, cut at 120 characters, else its kind), and `tubes[].label` is the edge label (else `"<from> → <to>"`) with `display` `"<from> → <to>"`. Tube ids are make-diagram's edge or message ids. `focus` has every node, group and participant id, every edge or message id (a view of the whole route) and every label, lowercased. `fallback` is `{ kind: "svg", svg, css }`: make-diagram's drawing, `css` once per page. Frames and notes are not drawn in 3D.
- **Dashboard lift.** `kind` is `"chart"`; the chart is one make-dashboard chart (a `.json` path plus a chart id), drawn in a plot 12 wide (x), 6 high (y) and as deep as it has series (z, 1.6 per lane, at most 9). `y = 0` is the floor, every height scale starts there, and a negative value hangs below it; the floor is a `line` platform 0.1 thick whose top is y = 0 (kept clear of the plot when any value is negative: four thin edges at y = 0 instead), with `grid` rules on the back wall at every value tick. `items[i]` is the chart's row `i` (a row with a null number is not drawn but stays in the table; a histogram's items are its bins), `label` is `"<x> · <colour>"` (just the x or colour value when there is only one), `value` is the row's number (`y`; the heatmap `value`; the bin's row count) and `display` is that number exact through `displayValue` (en-US grouping) with the scene spec's `units`, else `USD` for a `format: "currency"` chart, else none. Scatter and bubble say both axes: `"units 11 · amount 214.5"` (a bubble adds `· orders 4`). `graph.groups` are the colour values in ascending order, which is how the 2D chart assigns its colours, so a colour is the same in 3D and in `fallback` (one group named for the y column when there is no colour; a donut's groups are its segments), `labels` are the value ticks, the x ticks (at most 12), the lane names and the axis titles. Mapping: `bar` is one box tower per row; `stacked-bar` stacks them in one column per x (positive values up from 0, negative down; the last colour at the floor, as the 2D chart stacks); `grouped-bar` gives each colour a lane (z); `histogram` bins the values (`niceStep(range / 20)` edges, so bins can differ slightly from the dashboard's own; values that differ by a few dozen ULPs or less are one bin) into touching towers whose value is the row count; `line` is one tube per series (one lane per colour) with a sphere marker carrying the item on every point; **`area` is the same ribbon at 1.6 times the line radius (0.096 against 0.06), with no translucent surface**; `scatter` and `bubble` are spheres on numeric x and y axes from 0 (a bubble's diameter is `1.5 * sqrt(size / max size)`, at least 0.12, so area follows size) with one lane per colour; `heatmap` is one `surface` on the terrain grid convention, without its ring of empty cells (x and y categories ascending as the 2D chart's axes are, x along x, y along z, at most 20000 cells, a data cell on every 5th vertex, nearest-cell plateaus, height = value / max, `cells` row-major `gi * cols + ti`, accent bands), so a negative heatmap value is rejected (a surface cannot go below y = 0); `donut` is one tube arc per segment (radius 0.55 around a ring of radius 3.2, in ascending name order from 12 o'clock as the 2D chart stacks it, `item` set so it is hoverable, a 0.035 rad gap between segments), and a zero value has an item but no arc. A value too small to see is drawn 0.05 tall so it is still a marker. Boxplot and hand-written `vegaLite` charts are rejected; a lift takes at most 2000 rows and 24 groups. `focus` has every x value, every colour value (a heatmap's y values) and every item label, lowercased. `fallback` is `{ kind: "svg", svg, svgDark, columns, rows }`: the chart's own drawing in the light and the dark theme (distinct ids; the page shows the one that matches the theme) and the plotted columns as a table. **When Vega cannot draw the chart** (values too close together for an axis, which makes a NaN number format) the fallback is `{ kind: "table", columns, rows }` with no `svg` or `svgDark`: the plotted table alone, and the 3D scene is unaffected. Only that one known failure is handled this way, with a single `note: <chart>: drawn as a table in the fallback because its values are too close together for a 2D chart` line on stderr; any other drawing failure stops the build. A consumer must not assume `fallback.svg` is present.
